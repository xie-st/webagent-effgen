## 当前版本和编号大版本有什么区别

| 项目 | 当前版本 | v1、v2 等编号大版本 |
|---|---|---|
| 用途 | 持续开发的工作目录 | 保存一个阶段的完整成果 |
| 平时是否修改 | 是 | 保留当时状态 |
| 是否包含完整代码 | 是 | 是 |
| 默认运行哪个 | 当前版本 | 需要指定版本 |
| 何时创建 | 已建立，固定使用 | 用户决定阶段完成时 |

当前版本初始复制自 v1。两者是独立文件，不会互相同步；之后修改当前版本，不会改变 v1。

在项目根目录执行：

```powershell
python webagent.py check
python webagent.py test
python webagent.py connect
```

三条命令分别检查、离线测试和连接赛方，默认都选择当前版本。查看或运行已保存版本时加 `--version v1`。

保存下一个大版本：

```powershell
python webagent.py new-version v2
```

完整复制当前版本的代码、SDK 和测试，排除连接凭据、虚拟环境与运行结果。同名版本不会覆盖；保存后默认入口仍是当前版本。当前只有 `当前版本/` 和 `v1/`，尚未实际创建 v2。

## 测试结果存在哪里

统一入口是 [01_文本/05_测试结果](01_文本/05_测试结果/README.md)。

| 测试方式 | 保存位置，相对项目根目录 | 保存内容 |
|---|---|---|
| `python webagent.py connect` 线上连接 | `01_文本/05_测试结果/runs/<运行ID>/` | 版本、Git 信息、代码快照、会话状态；官方报告放该目录的 `raw/` |
| `python webagent.py test` 本机离线协议测试 | `01_文本/05_测试结果/runs/<运行ID>/` | `run.json`、`result.md`、`test-output.txt`、完整源码快照 |
| 本地练习运行器、`runner-smoke` | `01_文本/05_测试结果/local/<运行ID>/` | `run.json`、`result.md`、动作日志、浏览器回放与部分源码快照 |
| `smoke`、`browsergym` 环境检查 | `01_文本/05_测试结果/environment/<运行ID>/` | `run.json` 和对应检查报告 JSON |
| 已收录的历史测试 | `01_文本/05_测试结果/historical/` | 旧官方成绩与旧本机测试摘要、原始资料 |

`runs/` 同时保存线上会话和离线协议测试，读取该次 `run.json` 的 `kind` 区分：`official` 是线上会话，`infrastructure` 是离线检查。连接成功或客户端退出不等于官方任务通过。

### 线上成绩如何保存

1. 在项目根运行 `python webagent.py connect`，终端会显示本次结果目录；当前版本会自动建好 `raw/`。
2. 在赛方平台发起测试。测试完成后下载官方报告，放进本次结果目录的 `raw/`。
3. 在本次 `result.md` 记录任务、通过率、耗时、调用量和结论；在 `run.json` 的 `platform_run_ids` 记录平台批次编号。一个连接会话对应多个平台批次时逐项记录。

**目前不会自动下载官方成绩。** 自动保存的是代码和连接会话信息；官方成绩以平台导出为准。预先建目录可用 `python webagent.py new-run --kind official`，这只预留位置，不代表已测试。

已有历史官方批次 [ypgf_v0](01_文本/05_测试结果/historical/batch-8ed63eb9d774f28ba098cfa7bb4f8e9c/result.md) 存在于 `historical/batch-8ed63eb9d774f28ba098cfa7bb4f8e9c/`：4 项通过 3 项，原始导出在其 `raw/`。该批次未绑定到当前版本或 v1。

### 怎么找到刚才的测试

每次命令结束会打印结果路径。`index.jsonl` 索引根入口创建的 `runs/` 运行，`latest.json` 指向其中最近创建的一次；它们目前不索引 `local/` 和 `environment/`。后两类按各自运行目录时间查找。运行目录名采用 UTC 时间，比北京时间早 8 小时。

根入口始终使用统一结果目录。直接在版本文件夹运行 `python run.py test` 或 `connect` 时，默认写入该版本的 `results/runs/<运行ID>/`；使用 `--results-dir` 可另选位置。本地练习脚本也支持指定结果位置，以实际打印路径为准。`check` 只检查配置；单独启动练习站 `site` 只提供网页，两者不会生成任务成绩。工程检查 `python -m unittest ...` 输出到终端。

每次线上连接或版本离线测试保存当次完整代码快照，所以即使都叫“当前版本”，也能查到每次实际用了哪份代码。本地练习运行器只保存决策模块及 runner 快照，环境检查只保存报告；这两类脚本测试没有大版本成绩归属。

2026-10-30 核对：本机 HEAD 与实际远端 main 均为 `963243f`（`Document public repository visibility`）。刚才的目录整理、完整版本、当前开发目录及本文仍在本机工作区，**尚未提交，也尚未推送**。这个状态说明对应本次维护；以后以 `git status` 为准。

| 操作或文件 | Git 中的含义 |
|---|---|
| 修改当前版本 | 改动本机工作区；不会自动上传 |
| `new-version v2` | 新建完整阶段目录；不会自动提交或推送 |
| Git 提交 | 为整个仓库保存一次修改记录，不要求每次都建大版本 |
| Git 推送 | 将已有提交同步到远端 |
| 源码、SDK、文档、结果摘要与元数据 | 按当前规则可提交，不代表新文件已经提交 |
| 连接配置、令牌、虚拟环境、缓存 | `.gitignore` 排除，仅留本机 |
| `snapshot/`、`raw/`、详细动作日志与浏览器回放 | 仅留本机；摘要与元数据可提交 |

**编号大版本、Git 提交和测试快照是三件事：**大版本保存阶段代码；Git 记录整个项目的修改历史；测试快照保存某次运行实际使用的代码。可以提交日常修改，而不创建新的大版本。

克隆远端仓库只能得到已提交并推送的内容，不包含本机忽略的环境、原始测试资料和源码快照。
