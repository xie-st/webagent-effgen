# 模型与工具方案调研

更新：2026-10-29。依据[验收说明](../比赛要求/结构化资料/05_WebAgent赛题验收说明.md)与[接入指南](../比赛要求/结构化资料/04_WebAgent评测平台接入指南.md)，调整原模型与执行器选型。

## 当前判断

**以官方连接包和统一模型 baseline 建立参赛基线，主模型固定为 Qwen3.6-35B-A3B。** 首轮比较转为同模型下的规划、观察、检验、恢复与调度策略，不再比较不同主模型。

自动化平台负责网站、浏览器、模型与判分，本地实现决策逻辑。真实网站演示单独准备可接管、多 Tab 并行的浏览器执行能力，并沿用统一模型要求。

## 自动化接入

| 环节 | 当前实现方向 |
| --- | --- |
| 连接 | Python 3.10+，通过客户端主动连接；连接配置绑定本队账号。 |
| 决策入口 | 在 `agent_logic.py` 的 `decide(task, observation, history, action_history, state)` 中接入策略，沿用实际包中的函数签名与字段。 |
| 模型 | `third_party_agent.model.generate(messages)`；模型及推理参数由平台固定。 |
| 页面观察 | 当前为可访问性树文本、URL、页面类型与元素编号，提取必要信息进入上下文。 |
| 动作 | 每请求一个合法动作；元素编号来自当前观察。不能直接套用自带浏览器或截图坐标执行器。 |
| 状态与恢复 | 使用任务内 state 保存计划、进度、待确认动作和恢复点；写操作前后核对状态，避免重复。 |
| 评估 | 官方程序结果为准；保留动作日志、回放、通过任务耗时、模型调用量与 token。 |

现有 Browser Use、Playwright、Stagehand 等调研保留为模块设计与本地真实网站执行参考。完整框架能否迁入平台需核对观察、动作和模型回调，不能因原题允许页面脚本就默认平台提供任意脚本或浏览器控制权。

## 真实网站执行

验收现场公布目标网站与任务。实现上需具备真实导航、检索、多页面与子任务调度、限流控制，以及登录／二次验证时暂停、接管、恢复。演示需展示相对串行的耗时收益，操作与日志可对应。

自动化接入指南不提供可手动操作的实时论坛浏览器窗口，不能用它替代真实网站接管演示。真实网站的统一模型调用路径及 API Key 使用方式待赛方明确；不自行改用其它外部服务。

## 首轮验证口径

先运行官方 baseline，确认连接成功、实际产生网页动作、校验器判分和日志回放可用。当前接入指南的整批调测为固定 10 项论坛任务，每项浏览器就绪后限时 300 秒；最终验收用例包含论坛与电商，不能把调测任务表当作最终任务表。

在相同模型、任务、初始状态和判定条件下比较策略。记录任务 ID、操作时间、页面、动作、结果、模型调用量、token 和失败位置。每队同一时间只运行一个官方评测任务；并行收益在用例内部验证，平台支持情况先核对协议。

## 原调研的归属

2026-10-28 对 BU、Qwen3.8、Fara、MolmoWeb、Holo 等模型的比较属于统一模型要求明确前的探索，退出当前参赛选型。原稿保存在[更新前版本](../历史版本/2026-10-29_验收说明更新前/策略讨论/02_模型与工具方案调研.md)，一手证据仍保留于[模型核查](调研记录/2026-10-28_模型候选核查.md)和[工具核查](调研记录/2026-10-28_工具与证据核查.md)。

轻量辅助模型须报备；当前不据旧参数上限推荐替换统一主模型、自行调用其它 API、训练或调整平台模型推理参数。本轮仅更新文档，尚未运行 baseline 或验证框架适配。
