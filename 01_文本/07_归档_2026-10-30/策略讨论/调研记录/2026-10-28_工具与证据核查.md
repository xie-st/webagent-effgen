# 工具与证据核查

日期：2026-10-28。任务：支撑精力分配第一项的模型与工具筛选；本轮只调研，未安装、部署或实测。依据为指定赛题材料、搜索提示词、根协作规则和研究评估指导。当前结论见上级目录 `模型与工具方案调研.md`。

## 一、约束如何影响筛选

模型总参数原则上不超过35B；MoE放宽幅度未明确。采用完整权重规模核查，不能用激活参数或量化文件大小代替。API必须锁定可核验规格的模型，框架的默认模型、页面提取模型和备用模型也计入核查范围。网页DOM、页面脚本、模拟输入均可用；业务写入走网页，不开放直改数据库、伪造响应或直接调用后台写接口的工具。

本地依据：[整体理解](../../赛题理解/整体理解.md)、[精力分配](../精力分配.md)、[比赛要求汇总](../../比赛要求/WebAgent比赛要求.md)。上述接口取舍为本轮实现判断，不是新增官方条款。

## 二、工具事实与选用判断

| 方案 | 核实到的能力及获得方式 | 对本赛题的判断 |
| --- | --- | --- |
| Browser Use 开源Python库 | MIT；可选模型、本地浏览器与自定义工具。商业Cloud Agent、浏览器托管与开源库是不同交付物。[仓库](https://github.com/browser-use/browser-use) | 最快建立完整观察—决策—行动闭环的首选候选。使用显式模型配置。 |
| Browser Use 参数与历史 | 支持视觉开关、每轮多个动作、超时、失败次数、会话保存、成本统计；`page_extraction_llm`可单独配置；`fallback_llm`主要处理推理服务错误。[参数](https://docs.browser-use.com/open-source/customize/agent/all-parameters) | 可复用调用和执行骨架；模型服务切换不等于业务失败恢复。 |
| Browser Use 结果 | 历史含URL、动作、截图、错误、时长；`is_successful()`为模型自评。[输出格式](https://docs.browser-use.com/open-source/customize/agent/output-format) | 补时间戳、任务ID、模型ID与token统计；完成后用页面业务状态验收。 |
| Playwright | 动作前检查可见、稳定、可交互等条件；trace可查看动作与页面快照。[自动等待](https://playwright.dev/docs/actionability)、[trace](https://playwright.dev/docs/trace-viewer) | 适合作为确定性执行和回放基础；这些检查确认能操作，业务完成条件另设。 |
| Playwright MCP | Apache-2.0；提供无障碍树与浏览器工具，无需视觉模型；官方同时提供CLI路线。[仓库](https://github.com/microsoft/playwright-mcp) | 适合已有agent循环直接接入；自建工程可以直接使用库，无须为了比赛额外引入MCP。 |
| Stagehand v4 | MIT；`act/observe/extract`结合程序与模型；支持本地运行。自托管模型走自定义推理回调，回传JSON schema对应的结构化结果；默认Model Gateway会自动选模型。[仓库](https://github.com/browserbase/stagehand)、[v4模型文档](https://docs.stagehand.dev/v4/configuration/models) | 程序化方案的有力备选。禁用自动选模，以回调固定合规模型；不要照抄v3的baseURL配置。 |
| agent-browser | Apache-2.0；无障碍快照、元素引用、批量动作、条件等待、独立session、标签绑定。[仓库](https://github.com/vercel-labs/agent-browser) | 精简自建agent执行接口的候选。使用局部快照和批量动作是工程方向，未实测节省比例。 |
| Page Agent | MIT；页面内JS读取文本DOM，不依赖截图；可接本地模型，扩展支持多页任务。[仓库](https://github.com/alibaba/page-agent) | 轻量DOM路线备选；比赛跨站控制宜通过其扩展或外部执行器集成。 |
| Skyvern | AGPL-3.0；支持表单、结构化提取、工作流，以及Ollama/OpenAI兼容接口。[仓库](https://github.com/Skyvern-AI/skyvern) | 可复用工作流思想；第一轮先用更直接的执行骨架，降低集成变量。 |
| Magnitude | 视觉优先；官方推荐模型包括Sonnet和Qwen2.5-VL-72B。[仓库](https://github.com/magnitudedev/browser-agent) | 本次未取得其与合规模型组合的可靠性证据，先保留为工具参照。 |

## 三、补充模型：Fara1.5

[官方模型卡](https://huggingface.co/microsoft/Fara1.5-27B)、[执行代码](https://github.com/microsoft/fara)、[论文及附录](https://arxiv.org/html/2606.20785v1)。Fara1.5提供4B、9B、27B，MIT；27B完整权重统计为27,356,728,560参数，2026-10-28读取[官方API](https://huggingface.co/api/models/microsoft/Fara1.5-27B)。可自托管，通过官方fara/Magentic-Lite执行；截图与URL输入，坐标及键盘动作输出。宜保持官方工具协议，参考1440×900分辨率。

官方报告27B在WebVoyager为89.3%、Online-Mind2Web为72.3%；9B为86.6%、63.4%。论文按实时网页任务刷新、三次运行均值、各基准官方LLM judge计分，使用Browserbase并对网站阻断任务另行重跑；WebTailBench还区分过程与结果。以上不换算为本赛题程序验收成功率。

作者延续Fara-7B的数据生成路线，用真实网站及合成业务环境扩大行为覆盖，并筛选正确、有效率、符合交互要求的轨迹；与本次需求最相关的成果是可直接运行的小型网页操作模型。核心能力证据评分8/10，足以进入候选；本轮不展开训练方案。

## 四、如何判断“可靠完成”

[WebArena](https://github.com/web-arena-x/webarena)提供购物、论坛、GitLab、CMS等模拟站及812项端到端任务，任务形态更接近赛题；[BrowserGym](https://github.com/ServiceNow/BrowserGym)统一多类网页环境；[AgentLab](https://github.com/ServiceNow/AgentLab)支持实验、轨迹检查及版本记录；[WorkArena](https://github.com/ServiceNow/WorkArena)覆盖企业业务与组合任务，需配置ServiceNow实例。复用评测接口与日志方法即可，不把完整基准部署当成本轮前置任务。

第一轮候选比较应固定同一任务、初始状态、时限、步数和验收条件，记录整任务通过率、已通过任务耗时、模型调用量以及失败位置。优先覆盖跨站读取后创建、批量表单、状态修改、分页筛选；再加入一次超时、弹窗、元素变化或登录中断，观察能否接续完成。此处为选型验收口径，尚未执行。

核查评分：工具能力与接入方式9/10；Fara公开实验对候选资格的支撑8/10。评分为本轮研究判断，均不代表比赛通过率。核对完成：参数口径、开源与商业交付、默认隐含模型、工具协议、评测任务及成功定义均已区分。
