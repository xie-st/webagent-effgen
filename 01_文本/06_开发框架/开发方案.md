## 开发顺序

当前实现是单 Tab baseline，已有模型决策、短记忆、动作校验和重复动作提示，尚未接入 EffGen。历史未优化 EffGen 的初始成绩是 3/4、75%，用于了解现状；新实现另留可复现基线。

| 优先级 | 先做什么 | 原因 |
|---|---|---|
| P0 | 单步接口、统一状态、模型适配、日志与测试关联 | 后续模块都要接在这套骨架上 |
| P0 | 逐项确认目标、核验动作效果、局部恢复 | 先减少漏项、误停和重复提交 |
| P0，同步准备 | 真实浏览器、人工接管、限流，随后接多 Tab 调度 | 真实网站演示需要这些能力 |
| P1 | 历史去重、按需语义检查、少量已验证技能 | 基础闭环稳定后，逐项比较收益 |
| P2 | 区域检索、动态重规划、离线技能提炼、计划成本估计 | 按实际失败和耗时决定是否加入 |

自动化评测按单任务、单 Tab、单请求单动作执行，使用统一 Qwen3.6-35B-A3B。当前调测默认 300 秒，截止时间优先读取请求。真实网站路径承载并行与用户接管。

## 接口与共享状态

保留 `decide(task, observation, history, action_history, state)`。入口把输入转为 `Frame`，调用 `Runtime.advance(frame, state)`；官方出口只返回 `{"action": "..."}`。

M0 的 Runtime 注入 baseline 决策接口，沿用现有策略；M1 再将该接口替换为 EffGen policy。M0 不依赖尚未实现的 policy，也不新增运行依赖。现有 memory 统一由 TaskState 承接。

M0 实际调用链为 `MyAgent.step → official.frame_from_request → Runtime.advance → baseline.decide`。旧 `agent_logic.decide` 签名作为兼容入口，同样转交 Runtime；`agent_logic.model`、`SYSTEM`、`validate_action` 继续导出。公共校验在 `actions.validate_action`，Runtime 在合并 memory 前校验动作；baseline 纠错也共用该规则。官方入口保留 run_id 检查，reset/close 清理任务状态，close 后须再次 reset。

| 对象 | 内容 |
|---|---|
| `Frame` | 任务、run/step、URL/Tab、观察版本、AX 原文与当前编号、截止时间、平台能力、可取得的上一动作回执 |
| `ActionIntent` | 动作、语义目标、任务参数、所用观察版本、前后条件、所影响的业务对象 |
| `Proposal / Decision` | 模型候选及状态修改建议；runtime 校验后决定行动、完成、暂停、等待或退出 |
| `CheckResult` | `satisfied / unsatisfied / unknown`、对应要求或动作、证据、错误分类、后续提示 |
| `NodeResult` | 子任务状态、具体输出值、URL 与证据、未解决条件、耗时与调用量 |

`TaskState` 是任务事实与进度的唯一来源，保存在现有 `state` 中：

M0 已由 TaskState 承接 memory、恢复计数和剩余时间；下表其余目标状态按 M1–M4 逐项建立。当前 Frame 保存 AX 原文，当前编号由 `observe.build_context` 提取到 Context，禁止将历史编号当成当前编号。

| 状态 | 保存什么 |
|---|---|
| `goal_checks / facts / evidence` | 用户要求、条件分支、已证实事实及步骤/URL/观察片段 |
| `plan / active_node / processed_keys` | 子目标、依赖、输入输出、已处理对象 |
| `pending_effects` | 已发出但未确认的动作及预期效果；每个 Tab 至多一个 |
| `pages / skill_run` | 页面身份与观察版本；技能版本、参数、执行位置 |
| `budget / control / errors` | 截止时间、调用与访问、等待、暂停区间、错误和恢复点 |

模型和各模块提出修改，由 runtime 汇总、state 更新。页面证据成立才确认完成；`reset` 新建任务状态，`close` 关闭资源。页面、对象身份变化或人工接管后，重新核验受影响状态。历史保存语义和证据，当前编号每轮重绑。

模块入口沿用以下关系：`observe.build → Context`；`policy.propose → Proposal`；`verify.check → CheckResult`；`recover.choose → RecoveryPlan`；`skills.next → ActionIntent`；`scheduler.ready → 可派发节点`。

M0 已落地的观察函数名为 `observe.build_context(frame, state)`，决策端口为 `decision_port(context, TaskState)`，返回动作和可选 memory 提议；Runtime 统一校验、合并并返回单动作。上列 policy、verify/recover、skills、scheduler 是后续阶段接口，不表示已实现。M1 仅在 M0 主线程验收通过后接入 EffGen 决策端口。

`Context` 保存当前观察、可用编号、历史和决策输入。官方适配显式声明单 Tab、无原生暂停、无当前截图接口；上一动作回执可空，不将缺失回执当成成功。M0 Decision 只输出 action/stop，暂停和等待随后按真实浏览器能力实现。

模型统一经 `ModelPort.generate(messages, purpose, deadline)` 调用；浏览器提供观察、执行、暂停和恢复。内部暂停与等待由真实浏览器驱动处理，官方适配按平台能力输出合法动作。预算耗尽单独记录结束原因。

## 调用流程与 EffGen 接入

```text
官方：MyAgent.step → 官方输入适配 → Runtime → 单动作输出 → 平台执行
                                     ↑                     │
                                     └──── 下一次观察 ──────┘
真实网站：浏览器观察与回执 → 同一个 Runtime → 浏览器执行或暂停/等待

Runtime：
新观察 → 核验上一动作 → 更新状态与预算
       → 恢复 / 继续技能 / 普通决策
       → 当前编号、范围与前置条件检查 → 发出一个动作，登记待确认效果
       → 准备结束时核对全部要求；缺项则继续
```

动作发出后，等下一份观察确认效果；最后一个写动作也如此。当前完整 AX 指平台给出的视口观察，目标缺失时滚动寻找。当前观察和历史差异分开使用。

EffGen 首版采用无工具的单轮决策方式。以 **v1.3.0** 为接入起点，使用公开 `AgentConfig / Agent.run()` 和自定义 `BaseModel`；无工具分支进入直接推理，跨轮状态由项目外层维护。[源码依据](https://github.com/ctrl-gaurav/effGen/blob/v1.3.0/effgen/core/agent_react.py)

- 配置单 Agent、空工具列表，关闭自动子代理、额外记忆生成、能力探测和模型切换。JSON 解析与纠错交给 runtime。
- 官方模型适配只在 SDK 当前绑定线程内同步调用 `third_party_agent.model.generate(messages)`，发送合法字符串 messages。模型、采样和原生工具参数由平台控制。
- 普通有效决策目标为一次模型调用。规划尽量与首动作同轮产生；纠错、语义核验和恢复共用调用网关、时限和日志。
- 实际 token、费用暂记 `null`，按官方报告可取得的粒度补齐；估算单列。M1 验证调用次数与输出行为后锁定依赖。

真实浏览器沿用这套单步核心，接赛方允许的统一模型服务。本地脚本和假模型用于控制逻辑检查；模型入口接通后，再测 Agent 整项完成情况。此前可用官方平台验收模型端到端行为。

## 方法取舍

沿用[已有研究判断](../03_策略讨论/优化思路.md)，先接可组合的小机制。

| 阶段 | 方法 | 接入内容 |
|---|---|---|
| M2 | FCPAgent、ContractSkill | 子目标成功/失败证据，动作前后核验，局部修复 |
| M2 | Art of Building Verifiers | 先列用户要求，过程与终态分开，结束前逐项补证据 |
| M3 | MACU、ParaGUI | 无环依赖图、就绪派发、具体结果与证据交接 |
| M4 | 预算研究、Read More, Think More | 先去历史重复，保留当前 AX，统一统计全部模块成本 |
| M4 | CUA-Skill、ContractSkill | 少量短流程，参数与执行位置，逐步核验和退出 |
| 按需 | Region4Web、SGDR、Trace2Skill、JIT | 长页再做区域展开，技能增多再做检索，轨迹积累后再提炼 |

验证、恢复和技能共用同一份状态与证据。辅助模型、整站爬取、完整程序编译、多候选仲裁和在线自学习暂缓。

真实网站先并行独立读取。依赖必须存在且无环，验证完成才放行下游，失败只阻塞相关后继。worker 使用局部状态快照，主调度器串行合并带版本的结果，拒绝已取消节点的迟到输出。

节点声明 `read_set/write_set`，同一业务对象的读写或写写冲突串行处理，锁覆盖重读、修改到结果确认；对象不明时按账号/站点锁定。页面各自操作，共用站点限流器；429 优先按可取得的 `Retry-After` 等待，否则按配置退避。

人工接管时停止新动作和新模型决策，等在途操作结束后保存进度；恢复时重新观察。模型调用默认串行，浏览器 I/O 可以并行。

## 里程碑

依赖：`M0 → M1 → M2`；M3 的浏览器准备可从 M0 同步开始，完整并行依赖 M1、M2。M4 在 M2 后逐项验证，最后进入 M5。

| 阶段 | 改动与交付 | 验收 |
|---|---|---|
| M0：核心骨架 | 建立 contracts/state/runtime/observe 和官方适配，以注入的 baseline 决策接口驱动 Runtime，统一 memory，保留现有入口 | 新增 Frame 映射、Runtime baseline 接线、单动作与有效决策单次模型调用、reset 隔离测试；保留原校验/纠错/记忆行为；入口与独立复制测试通过 |
| M1：EffGen 接通 | 实现 policy、模型适配、固定依赖和环境检查 | 真实 EffGen＋假 SDK 下，有效决策恰好一次调用，连续观察保持状态；SDK 子进程绑定与独立运行通过；官方任务留下新基线 |
| M2：确认与恢复 | 接入 goal_checks、pending、verify/recover；负责在本地 bench/cases 增加无效果、结果不明、缺项目标、重复写入场景与判定器 | 未生效动作不推进进度，缺项不能成功停止；结果不明先查证；恢复后继续并完成，避免重复写入 |
| M3：真实网站 | 实现 browser、scheduler、接管与限流，接统一模型和主循环；记录真实目标、统一模型接入、限流及时限的已知条件与待确认项 | 独立、带依赖、纯串行三类任务；依赖失败阻塞，共享写入无冲突；真实任务同标准完成，并行分支减少实际耗时；本地与真实网站证据分开，外部必要条件未满足则 M3 保留未完成 |
| M4：效率优化 | 分别加入历史 diff、按需检查和少量技能，做成对比较 | 完整通过保持或提高，同时改善耗时或用量；技能自身完成与基础代理补救分开记 |
| M5：交付 | 复核工程、官方结果、真实演示和 3–5 页报告 | 官方可用套件顺序跑完并保存原件；真实演示有多 Tab、耗时对照、限流与接管；代码可独立启动，日志与成绩对应 |

## 阶段复核与记录

参考 Gabriel Chua 的[里程碑协作方式](https://www.linkedin.com/pulse/collaborating-codex-long-running-tasks-gabriel-chua-unpec)，同学结合路线图自行选择工作，沟通目标、改动范围和验收方式。agent 接到委托后推进当前目标，并随新证据主动维护本方案：当前阶段、完成证据、未完成项与阻塞、下一步。

协调讨论聚焦目标、约束、决定和进度；交接说明改动文件、验证结果、未完成项和下一步。浏览器、登录和接管行为在对应环境实测，具体要求见上方验收。

阶段结束后分别检查代码正确性和路线图完整性，由另一位同学复核：交付是否完成、接口是否一致、证据是否对应代码，下一阶段与验收是否仍合适。agent 据此更新方案；未完成项留在当前阶段，后续工作在已授权范围内推进。

进度和决定直接更新本文，README 维护入口与运行方法，测试目录保存证据。用户决定保存阶段成果时，再创建完整编号版本，随后继续开发当前版本。
