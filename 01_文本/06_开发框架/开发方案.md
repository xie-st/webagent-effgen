## 核心架构

官方评测与真实网站共用 Runtime 和任务状态，由各自适配器处理输入与执行。

```text
当前调用：MyAgent.step → official.frame_from_request → Runtime.advance
                                                      ├─ observe.build_context
                                                      ├─ EffGen policy → ModelPort → SDK
                                                      └─ actions.validate_action → 合并 memory → 单动作输出

后续接入：EffGen policy → verify/recover → browser/scheduler → 效率优化
```

| 模块 | 职责与实现状态 |
|---|---|
| `contracts.py`、`state.py` | 已实现 Frame、Context、Capabilities 与 TaskState；管理 memory、恢复计数和剩余时间 |
| `runtime.py` | 已实现观察组装、注入决策端口、动作校验与 memory 合并 |
| `observe.py` | 已实现当前 AX、当前编号、历史和决策上下文 |
| `baseline.py`、`actions.py` | 已接通现有策略与公共动作校验 |
| `adapters/official.py` | 已实现官方请求映射与能力声明；统一模型经ModelPort在SDK绑定线程调用。下一步接可选截图元数据与截图端口，当前运行尚未升级 |
| `policy.py`、`model_port.py` | M1a已接通真实EffGen1.3.0与统一SDK模型端口；后续规划与语义诊断 |
| `verify.py`、`recover.py` | M2 核对目标与动作效果，选择局部恢复 |
| `adapters/browser.py`、`scheduler.py` | M3 真实浏览器、接管、多 Tab 依赖与限流 |
| `telemetry.py` | M1a已实现调用/运行日志与生命周期，M2/M3扩展核验、浏览器与调度事件 |
| `skills.py` | M4 接入技能执行与复用 |

核心模块均放在当前版本的 `web_agent/` 内；提示、技能、配置和固定依赖随版本完整保存。根入口负责启动，SDK 保留原件，保存的大版本保留当时状态。本地环境与工程工具分别只维护一份。

保留旧入口 `decide(task, observation, history, action_history, state)`，统一转交 Runtime；`agent_logic.model`、`SYSTEM`、`validate_action` 保留兼容导出。新决策端口接收 `(Context, TaskState)`，返回动作及可选 memory；Runtime 先校验动作，再合并状态，每次只输出一个动作。

TaskState 是任务事实与进度的唯一来源。M0 已接管 memory、恢复计数和剩余时间；后续逐项加入目标与证据、计划与处理对象、待确认效果、页面与技能状态、预算与接管状态。模块提出修改，Runtime 汇总更新。reset 新建状态，close 清理状态与运行身份，close 后再次运行须 reset。

当前观察保留完整 AX，编号每轮重绑；历史只保留语义和证据。官方仍为单 Tab、无原生暂停；服务端已开放可选视口PNG，但我方M1冻结SDK尚未接通，当前代码的`screenshot=False`反映该运行状态。上一动作回执可空，缺失不视为成功；当前输出仍为单个action/stop。

## 截图接入与权重

截图是本次AX观察的补充证据，不改变统一模型、动作空间和完成标准。新版SDK已明确模型只收文本；不向ModelPort塞入PNG、base64或图片消息。399失败的错误值已出现在AX中，说明当前主问题是目标核验，M2优先级保持P0。

| 优先级 | 工作 | 完成依据 |
|---|---|---|
| P0：短准备 | 升级当前版本的官方SDK原件及SOURCE指纹，保留M1旧快照；透传可选截图元数据；同一令牌先停旧客户端再启新客户端 | 纯文本回归和SDK子进程绑定不退化；字段缺失可运行；不得用官方demo覆盖本项目EffGen入口 |
| P0：随M2接入证据 | 提供按需截图端口、观察绑定、完整性核验、缓存与耗时日志；默认不逐帧下载，AX证据不足、异常或诊断需要时触发 | 同一帧不重复下载；没有截图不沿用旧图；超时仍遵守原截止；下载失败可按剩余预算回到AX，不能当作目标成功 |
| P0：M2主线 | 用户要求覆盖、精确值核对、动作效果确认、结果不明查证及局部恢复 | 修复替换变追加、缺项误停和重复写入；网页实际结果证明完成，保存提示或截图存在不能单独证明成功 |
| P1：收益验证 | 在AX缺失或视觉歧义场景试本地OCR/图像提取，仅将必要文本事实交给现有主模型 | 固定新版SDK、任务和判定器，比较开启/关闭后的完整通过、总耗时与调用量；涉及辅助模型须按规则报备，不默认增加模型或依赖 |

新增边界安排在当前版本内，后续实现时同步调用方与测试：

- `Frame/Context`携带可空截图引用：image_id、mime_type、尺寸、字节数、sha256、截图step，并绑定run/Tab/观察版本和URL；历史保存引用及来源，不向模型或memory嵌入PNG二进制。
- `adapters/official.py`接新版`third_party_agent.browser`；截图端口在有效Agent回调及SDK绑定上下文内同步获取，和模型共用绝对deadline，禁止回调结束后后台下载。能力依据已安装SDK与本轮有效元数据判断，不因服务端公告就把所有观察标为有截图。
- Runtime在核验、恢复或诊断需要时申请截图，observe提供当前观察关联；SDK的`save_screenshot`完成格式、尺寸、字节数和SHA-256核验。截图存本次结果的`raw/screenshots/`并受Git忽略，TaskState只保留可失效的引用。
- telemetry单列截图请求、缓存命中、字节数、耗时、结果及关联观察；下载与本地处理计入同一300秒预算，不计为模型调用。ModelPort仍维持字符串消息和统一模型约束。
- M3真实浏览器沿用相同证据引用边界，截图获取由真实浏览器适配器提供；不据此推断官方开放多Tab、坐标、JS或CDP。

下一步先完成最小客户端兼容和元数据通路，再在M2中按需接入截图证据；OCR不作为M2前置。新版客户端的下一次平台回归另建纯文本参照，之后比较M2或截图机制时固定SDK与采集设置，避免把环境升级误记为算法收益。

## 后续接入约束

EffGen 首版以 v1.3.0 为起点，使用公开 AgentConfig / Agent.run() 和自定义 BaseModel，配置单 Agent、空工具列表；关闭自动子代理、额外记忆生成、能力探测和模型切换。跨轮状态由外层维护，JSON 解析与纠错归 Runtime。接入材料见[EffGen说明](../03_策略讨论/EffGen接入与开发.md)。

模型统一经 `ModelPort.generate(messages, purpose, deadline)` 调用。官方模型须在 SDK 当前绑定线程同步调用，messages 使用合法字符串；模型与采样参数由平台控制。有效普通决策目标为一次模型调用，规划尽量与首动作同轮输出；纠错、核验和恢复共用网关、时限与日志。实际 token、费用不可取得时记 null，估算另列。

M2 起，动作发出后登记预期效果，每个 Tab 至多一个待确认动作；下一观察核验后才推进，最后一个写动作也须确认。结束前逐项核对用户要求；结果不明先查证，避免重复写入。页面身份变化或人工接管后，重新核验受影响状态。

M3 先并行独立读取。依赖图必须无环，核验成功才放行下游；失败只阻塞相关后继。worker 用局部状态快照，调度器串行合并带版本的结果，拒绝已取消节点的迟到输出。节点声明读写对象，共享写入串行；锁覆盖重读、修改到结果确认，对象不明按账号/站点锁定。各页面共用站点限流器，429 优先使用 Retry-After，否则配置退避。

人工接管时停止新动作和新决策，等待在途操作结束后保存进度；恢复时重新观察。模型调用默认串行，浏览器 I/O 可并行。官方评测单任务、单 Tab、单请求单动作，使用统一 Qwen3.6-35B-A3B；当前默认 300 秒，请求截止时间优先。真实网站接赛方允许的统一模型服务。

## 里程碑与验收

顺序为 M0 → M1a → M1b → 新版客户端兼容 → M2 → M3a → M3b；截图证据随M2接入，OCR按需验证，不另占一个大阶段。M3浏览器准备须后续授权，本轮不启动。完整闭环与并行依赖M1、M2；M4在M2后逐项验证，最后M5。M1、M3各保留一个里程碑，分别在两个验收点通过后结案。

| 阶段 | 交付 | 验收 |
|---|---|---|
| M0：已完成 | 核心骨架、baseline 接线、共享状态与官方适配 | check、离线 21/21、独立复制 1/1 通过，见[M0结案](M0结案.md) |
| M1a：已验收 | policy、统一模型端口、固定依赖与环境检查、最低调用日志 | 真实 EffGen＋假 SDK 下有效普通决策恰好一次调用，纠错调用另计；连续观察保持状态；SDK 子进程绑定与独立运行通过；日志可核对调用次数、错误及结束原因 |
| M1b：已验收 | 固定 M1a 代码、依赖和运行条件，顺序运行官方可用套件 | 保存平台原件及逐项通过结果、耗时、调用量、结束原因，与本地日志对应，形成后续比较起点；[M1结案](M1结案.md) |
| 下一步：新版客户端兼容 | SDK原件与指纹升级、Frame可选截图引用、同步获取端口；保留已验收M1运行快照 | 不破坏原纯文本行为与单令牌单客户端；旧观察缺字段、当前帧绑定、PNG校验、重复抓取、404/409和截止均覆盖；相应平台实测后才能称截图链路已接通 |
| M2：确认与恢复 | goal_checks、pending、verify/recover；本地故障用例与判定器；按需截图证据 | 无效果不推进、缺项不能成功停止；替换值精确匹配；结果不明先只读查证，未知提交不重发，恢复保留已核实前缀；判定器从原任务核对覆盖，不能只信actor清单 |
| M3a：真实网站单 Tab 闭环 | browser、统一模型接入、观察与执行、复用 M2 核验恢复、接管与限流 | 真实任务完成观察→执行→结果确认，最后写入也确认；接管后可恢复，限流按规则等待；在相应环境实测并保存串行参照，本地与真实证据分开 |
| M3b：多 Tab 调度 | scheduler、依赖图、共享写入协调、跨 Tab 站点限流 | 独立/依赖/串行任务均验证；依赖失败阻塞，共享写入无冲突；同任务、同完成标准下对照串行/并行实际耗时，计入规划与汇总开销并证明收益；外部必要条件缺失时保留未完成 |
| M4：效率 | 分别加入历史 diff、按需检查、少量技能 | 成对比较，完整通过保持或提高，同时改善耗时或用量；技能自身完成与基础代理补救分开记 |
| M5：交付 | 工程、官方结果、真实演示、3–5 页报告 | 官方可用套件顺序跑完并存原件；演示多 Tab、耗时对照、限流与接管；代码独立启动，日志与成绩对应 |

优先做确认与恢复、真实浏览器与接管，再做历史去重、语义检查和少量技能。已有[方法判断](../03_策略讨论/优化思路.md)继续作为依据；区域检索、动态重规划、离线技能提炼和成本估计按失败与耗时决定。辅助模型、整站爬取、完整程序编译、多候选仲裁和在线自学习暂缓。
