# M2核验恢复替代方案与论文依据

2026-10-30 22:10（北京时间）；负责人：本机Codex。状态：研究建议，未实施、未验证收益。M3按用户要求暂停，已有代码及证据保留。本轮核对远端main `bf65496`、M2交接分支 `68f0892`、本地简化M2和M3工作树；不启动平台批次，不重试被拒推送。

## 结论

建议用**单个完整EffGen Agent＋明确语义的操作工具＋操作前后页面变化反馈**，替代现有全任务verify/recover控制流程。

任务理解、结果判断与异常处理统一交给持续运行的同一个Agent；外围程序只保证操作语义、记录网页事实、遵守官方单步协议和截止预算。精确值比较、已生效状态检测、未知提交保护保留，但移到对应操作内部，不再依赖自然语言目标分类和逐步证明协议。

这是基于下列论文组合出的项目设计，不是某一篇论文原样实现，也没有论文能直接保证本项目全部任务通过。与远端[完整EffGen单智能体Roadmap](https://github.com/xie-st/webagent-effgen/blob/bf65496/01_%E6%96%87%E6%9C%AC/06_%E5%BC%80%E5%8F%91%E6%A1%86%E6%9E%B6/%E5%AE%8C%E6%95%B4EffGen%E5%8D%95%E6%99%BA%E8%83%BD%E4%BD%93Roadmap.md)的方向一致。

## 论文出处及采用范围

1. **AgentOccam: A Simple Yet Strong Baseline for LLM-Based Web Agents**，Ke Yang等，2024预印本，本文核对2025年v2。[原文](https://arxiv.org/html/2410.13825v2)。采用其简化观察/动作表示、减少额外角色的方向。论文也报告Judge变体有收益，因此不能声称裁判普遍无效；本项目选择省去独立裁判，是针对预算与实际空转的工程取舍。不照搬其取消滚动：本项目完整DOM与可操作AX并不等价。
2. **Agent-E: From Autonomous Web Navigation to Foundational Design Principles in Agentic Systems**，Tamer Abuelsaad等，2024。[原文，尤其Change Observation部分](https://arxiv.org/html/2407.13032v1)。采用操作工具返回实际页面变化、按需整理DOM的思想；不引入其整套层级多Agent。其MutationObserver实现不能直接搬到禁止自定义JS的官方环境，改用相邻官方观察对比。
3. **ReAct: Synergizing Reasoning and Acting in Language Models**，Shunyu Yao等，ICLR 2023。[论文](https://arxiv.org/abs/2210.03629)、[作者项目页](https://react-lm.github.io/)。采用同一Agent在动作与外部观察之间持续更新计划、处理异常的循环；短进度和事实即可，不要求每轮额外生成长反思。
4. **CRITIC: Large Language Models Can Self-Correct with Tool-Interactive Critiquing**，Zhibin Gou等，ICLR 2024。[会议原文入口](https://proceedings.iclr.cc/paper_files/paper/2024/hash/fef126561bbf9d4467dbb8d27334b8fe-Abstract-Conference.html)。采用先获得工具外部反馈再修正的原则，不复制每步独立批评调用。论文实验涉及问答、数学程序和毒性降低，不能外推成网页任务效果保证。
5. **Large Language Models Cannot Self-Correct Reasoning Yet**，Jie Huang等，ICLR 2024。[会议原文入口](https://proceedings.iclr.cc/paper_files/paper/2024/hash/8b4add8b0aa8749d80a34ca5d941c355-Abstract-Conference.html)。作为边界依据：在其推理实验中，缺少外部反馈的自我纠正可能无效或退化；不能据此断言所有网页自纠错无效。

## 替代流程

```text
原始任务、约束与简短进度
           ↓
     一个持续运行的EffGen Agent
           ↓ 选择工具
  替换/追加输入、确保状态、提交、普通浏览
           ↓ 经官方桥接，每轮一个原始动作
    下一次AX / DOM / HTML观察
           ↓
  工具返回真实变化、值差异或结果未知
           ↓
     原Agent继续、修复、查询或结束
```

### 1. 用正确操作语义预防错误

以下是项目拟新增的逻辑工具，不是官方已有API，也不要求调用方写复杂证明JSON。

| 操作 | 最小语义与反馈 |
| --- | --- |
| `set_value(target, text, mode)` | 明确replace/append；replace执行选中并清除原值后输入，读回当前全文与期望值比较；append先读取基线，形成基线＋新增内容的期望全文，防止重试再次追加。观察不到完整值则返回unknown，不能以包含目标子串冒充相等 |
| `ensure_state(object, desired)` | 先定位同一业务对象及当前状态；已满足则不点击，未满足才行动；不能把所有开关都当成无副作用草稿，checkbox可能自动保存。状态含义不明确时先查询或交回Agent |
| `commit(target)` | 记录本次提交与对象，等待后续业务读回；保存提示只是执行反馈。结果未知时先只读查询，不自动重复发送评论、订单等非幂等操作 |
| 普通浏览工具 | 导航、菜单、搜索等返回新页面和变化，不因为Enter或按钮名称就一律登记业务提交；不明副作用必须显式返回unknown，不默认为安全 |

工具参数由同一Agent根据任务和当前页面选择。工具层检查已知控件语义与可见状态；自定义控件或无明确证据的副作用无法靠名称可靠推断，必须承认unknown。这套工具减少故障面，不承诺完整识别任意网站业务。

### 2. 操作反馈只描述可观察事实

最小反馈包含：当前观察版本、业务对象、实际变化、实际值、状态。状态可用`changed / no_change / mismatch / unknown`，由代码在可确定的范围内产生；不等价于全任务成功。

例如399返回“当前简介全文为A＋B，期望为B”；404返回“帖子URL为X，点赞控件已处于撤销点赞状态”。同一Agent据此决定修复或继续处理最新排序等剩余要求，不再让另一个裁判重做整段任务理解。

事实须来自网页，标明步骤与来源。网页中的指令性文字属于外部内容，不替代用户要求。长页面按相关表单/对象摘要，完整观察仍外存可回查；历史AX编号不用于当前执行。

### 3. 恢复变成原Agent的正常下一步

- 输入全文错误：重新定位原字段，按replace纠正，再读回；不重做已完成的其他对象。
- 点赞已生效：记录该对象已满足，继续其他要求；不再次执行toggle。
- 元素失效、菜单未展开、无变化：重新观察并定位，针对实际变化采取下一步。
- 提交结果未知：查询同一对象的业务结果；无法确认则保留未决状态并以Incomplete退出，不能宣称成功或重发非幂等提交。

外围只维护当前工具续执行信息、未决写入及简短事实，不维护通用任务类型/语义证明状态机。设置有限的无进展预算，例如同一对象连续两次查询没有新事实就结束当前尝试；“两次”是待调参的工程起点，不是论文结论。任务绝对deadline仍有效，预算不足时正常Incomplete，不再开始注定超时的模型请求。

已确认是错误值可以修复；未知写入结果不能盲目重发。两者必须区分。缺少服务端幂等键和事务接口时，不能保证任意提交严格exactly-once。

### 4. 完成判断仍需覆盖原任务

Agent常驻原始请求及约束，维护简短的“已完成对象＋网页依据／剩余要求”。结束前由同一个Agent核对原任务；程序只硬性阻止已知矛盾、未决写入和越界动作，不再尝试用正则证明任意自然语言任务完整覆盖。

例如404“最新帖子”必须有排序和帖子身份依据，不能仅凭点赞状态结束。多对象任务按稳定业务URL去重并保留来源；“中性或正向”等语义仍由Agent结合帖子内容判断，无法用通用布尔工具保证正确。这个取舍必须通过新任务检验，不能以移除复杂核验宣称消除了所有错误完成。

## 新接口和官方协议适配

- AX用于当轮可操作元素和可得的当前控件值；DOM/HTML用于理解表单、标签、对象层次与页面内容。HTML属性不保证等于实时输入值，也不证明后端持久化成功。
- DOM的nodeId/backendNodeId不能当AX动作ID。对应不确定时重新观察，不猜编号；全文DOM不代表所有元素当前可点击。
- 官方每次step只允许一个原始动作。逻辑replace工具必须跨多次回调完成“定位/点击→全选/清除→输入→下一观察读回”，每步按当前页面重新绑定，不能在一次回调偷偷执行多动作，也不调用官方未提供的JS/CDP接口。
- 完整EffGen循环必须在发出动作后挂起，下一step将真实观察作为工具结果交回原Agent。统一模型仍在有效SDK回调线程中调用；reset、超时、取消清理旧续执行状态。
- 普通步骤不另调verify模型。总调用能否下降、是否增加页面读回步骤都须实测；不预报固定降幅。

## 对现有代码的迁移边界

保留统一模型适配、SDK、动作格式校验、当前观察封装、deadline、日志和任务隔离。将`verify.py`中的通用目标抽取、历史证明校验和全局stop裁判移出默认路径；将`recover.py`中的关键词分类、恢复计划和语义门禁替换为上述工具行为。精确比较、对象状态和未知写入逻辑只在其操作内保留一份。

`policy.py`应迁入完整EffGen工具循环，`runtime.py`收敛为官方协议桥接。旧契约不强求逐字段兼容；可保留离线旧基线供对照，但不将旧测试数量作为新方案完成证明。本轮不做代码迁移。

## 实施和验收顺序

1. 先验证一个完整EffGen工具循环跨官方多次step续执行；覆盖reset、取消、超时和观察版本，不并入M3多Tab。
2. 只实现replace/append和ensure_state，加新观察反馈，复现399/404，确认不误报完成、不撤销成功状态。
3. 加提交未知保护与无进展退出；回归650评论不重复、731追加不破坏原文，以及搜索Enter、菜单、自动保存checkbox和异步提交反例。
4. 冻结版本，使用相同SDK、模型、任务初始状态、截止时间，对照M1策略、旧M2和新方案；官方扩充8项都要跑，尤其数量、排序、筛选和跨对象任务，防止仅修好两个已知例子。

首要指标是平台任务成功率，其次错误完成、重复/撤销写入、正常Incomplete与异常超时，再比较总模型调用和总耗时。至少重复运行才能判断稳定性，固定样本与次数并报告波动；脚本替身、本地真实浏览器、官方真实模型成绩分开。可通过“只改语义工具／再加变化反馈”小型消融判断收益来源。
