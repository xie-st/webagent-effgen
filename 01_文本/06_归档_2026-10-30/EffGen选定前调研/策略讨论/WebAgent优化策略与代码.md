# WebAgent 优化策略与代码

2026-10-30 · 依据比赛要求、赛题整体理解及最终33篇论文。

**先把完成判定、状态记录和局部修复接成闭环，再压缩观察与模型调用；真实网站侧另接依赖调度和页面隔离。** 这些机制可以分别加入基础 Agent，共用任务状态与证据，避免叠加多个完整框架。

## 怎样叠到基础 Agent 上

以下为本项目的组合设计，分册给出各机制的原文依据和细节。沿用基础 Agent 的 `decide()`，在其外围增加观察、状态、检查和恢复，不要求替换整套执行器。

### 1. 先统一状态与证据

| 状态 | 保存什么 | 由谁使用 |
|---|---|---|
| 任务要求 | 原始目标、必须满足的约束、待完成项 | 规划、终止检查 |
| 子目标 | 依赖、当前状态、成功证据、失败证据 | 调度、检查、局部修复 |
| 当前页面 | URL、页面/Tab身份、观察版本、当前元素映射 | 定位、执行、页面展开 |
| 执行进度 | 已验证完成项、未确认动作、失败位置、已处理对象 | 恢复、上下文压缩 |
| 成本与时间 | 模型调用和token、页面访问、等待、动作、剩余时间 | 选择检查、调度和额外推理 |
| 技能执行 | 技能ID与版本、绑定参数、当前步骤、契约证据、退出原因 | 检索、逐步执行、修复与收益归因 |

“已经发出动作”和“证据确认完成”分开记录。页面元素编号属于当前观察，持久状态保存对象语义和证据，不复用旧编号。模型给出的摘要不自动成为已完成事实。

### 2. 接入检查与恢复

观察更新后，先处理上一动作的结果，再选择下一动作：

1. 程序检查协议、元素有效性和已定义谓词；当前证据足够时直接更新状态。
2. 结果不明、循环无进展、子目标切换或准备结束时，按需调用统一 Qwen 作语义诊断。
3. 检查未通过时，将失败证据和当前页面交给局部修复；保留与故障无关且已验证的进度。
4. 恢复后检查下一步的前置条件，再继续执行。最终 `stop` 前检查全部任务要求。

检查时机取 FCP 的按需诊断思想；检查内容取契约和完成验证；修复入口取 CUADebug 与 ReTRACE。它们共享同一状态表，不各自维护一份相互矛盾的“完成状态”。

### 3. 再减少观察与调用

以当前完整 AX 树作为可回退的观察基准，先减少历史冗余，再对长页面引入区域摘要和候选检索。目标元素缺失、检索失败或验证不通过时，扩大观察。不能仅因输入 token 下降就保留某种裁剪方式，要同时看完整任务通过和总耗时。

确定性状态更新、动作格式检查、元素编号校验、依赖阻塞交给程序；语义规划、歧义定位、异常解释交给同一主模型。额外候选采样和仲裁单独计费；固定模型和推理设置下，优化的是何时调用、给什么输入、需要多少输出。

### 4. 加入按状态调用的 Skill

开发阶段从实际轨迹提炼技能候选，保留适用状态、参数、操作要点、验证和恢复条件；用独立任务验证后进入版本化技能库。运行时按子目标与当前页面检索，只加载少量相关技能。技能选中后保存参数与执行位置，每次观察更新都重新绑定当前元素编号，只向平台返回一个动作。

Skill 与基础 Agent 共用完成谓词和证据账本。前置条件不满足、目标歧义或结果未通过时，暂停技能并交回基础 Agent；补救结果单独记账，不能用“Agent后来成功”证明技能本身可靠。完整字段、触发流程与代码入口见[Skill分册](论文策略与代码/Skill构建与复用.md)。

### 5. 接入任务内并行

真实网站侧先并行互不影响的读取和信息获取，再依据依赖合流。每个 worker 有自己的页面与任务状态；上游向下游传具体结果、证据和未解决条件。共同写同一对象的动作由调度器协调，不能仅因位于不同 Tab 就认定互不干扰。

自动化平台侧将计划与调度状态保存在本机，每次仍按协议只输出一个当前合法动作。群内答复已确认自动化评测网站不支持多 Tab，不开放 curl／JS 注入；截图后续可以提供，当前仍按已有 AX 观察接口适配。Tab 切换、并行操控与进阶方案在真实网站实现和展示；不并发提交多个官方评测任务。

## 接入顺序与保留标准

| 阶段 | 接入内容 | 用什么决定保留 |
|---|---|---|
| 基础记录 | 原始任务、观察、动作、回执、耗时与调用日志 | 能定位首个偏离点，能对应官方回放 |
| 成功闭环 | 完成谓词、动作结果确认、显式进度、局部恢复 | 减少误报完成和重复写入，增加完整通过 |
| 观察与成本 | 历史差异、区域展开、按需诊断、预算门控 | 通过率维持或提高，同时减少任务总耗时/总token |
| 技能复用 | 少量已验证技能、状态检索、动态绑定与逐步执行 | 固定任务和框架后，完整通过与总耗时/成本优于无技能配置 |
| 真实网站并行 | 依赖图、页面隔离、结果传递与冲突处理 | 相同成功标准下较串行缩短实际完成时间 |
| 离线迭代 | 故障归因、提示/钩子修改、独立任务回归 | 修正目标错误且未在其他任务产生退化 |

每次比较只改变一个机制或一组必须共同工作的机制，保存策略版本。先看整项通过，再比较双方均通过任务的耗时与成本，另保留全部任务的通过率；人工接管时段按比赛要求单独记录并扣除。
