# 规划、并发、执行与恢复：可接入基础 Agent 的方法

本组覆盖现行清单 01、02、04、05、08、13、17、18、28。以下“论文方法”为原文机制，“接入”为依据赛题设计的迁移方案；后者不是作者已验证的比赛实现。Skill 的结构、检索与学习机制另见[Skill构建与复用](Skill构建与复用.md)；本篇聚焦规划与执行闭环。

## 01 MACU：让并发围绕依赖和证据组织

**问题与判断。** 多个 Agent 同时工作不等于任务并行：后续子任务可能依赖前一任务才发现的信息，初始分解也可能被网页证据推翻。MACU 的关键对象是可动态修改的 DAG，而非固定角色列表。

**论文方法。** 管理器接收任务、当前 DAG 和节点最新观察；初次生成图，节点结束时结合末尾观察和回答重新规划，可增加、删除、取消节点，修改尚未执行节点的指令或依赖。每次图编辑消耗重规划预算，编辑后重新检查无环性。子代理执行同一类 ReAct 循环，差别来自指令与继承的环境；下游获得父节点留下的证据，而非只收到“已完成”。管理器还可要求已结束节点补充工作。

**接入。** 在基础 `decide()` 外增加 `TaskGraph`。节点保存 `id、goal、deps、status、inputs、result_evidence`；只有依赖均验证完成才进入 ready 队列。任务初始和节点状态变化时调用统一 Qwen 更新图，常规动作沿用基础 Agent。真实网站侧把节点分配给独立 Tab，输出 URL、提取值、证据位置和未解决项；合并节点据此核对总目标。自动化侧先用相同图管理待办并逐次返回一个合法动作，待协议核实后再启用真实并发。

共享账号、购物车或同一编辑对象的写操作需要互斥；为节点声明 `read_set/write_set` 并检查冲突，是我们的多 Tab 迁移设计。原文以隔离 VM 运行子代理，不能据此认为共享浏览器状态已解决。

**代码。** [作者仓库](https://github.com/kohjingyu/multi-agent-computer-use)，默认分支 `master`；从 [run_macu.py](https://github.com/kohjingyu/multi-agent-computer-use/blob/master/run_macu.py) 看运行入口，图与管理器模块位于 [utils](https://github.com/kohjingyu/multi-agent-computer-use/tree/master/utils)，提示词重点看 [manager_cua_v2.yaml](https://github.com/kohjingyu/multi-agent-computer-use/blob/master/prompts/manager_cua_v2.yaml)、[replan.yaml](https://github.com/kohjingyu/multi-agent-computer-use/blob/master/prompts/replan.yaml)、[followup.yaml](https://github.com/kohjingyu/multi-agent-computer-use/blob/master/prompts/followup.yaml)。优先借用图结构、编辑校验和证据交接，浏览器与模型层接赛方接口。

## 02 FCPAgent：把计划写成可被网页证据推翻的承诺

**问题与理论。** “正在执行计划”不能说明仍朝目标前进。每个子目标除了描述要做什么，还应说明什么证据支持它、什么证据将否定它。

**论文方法。** 一个 FCU 包含子目标、可选程序引用、确认证据、否定证据和置信度。确认分为前提、进展、完成；否定分为动作、程序选择、规划层。动作前检查候选动作，动作后检查网页状态。廉价筛查只决定是否送慢验证器，不能直接认定成功：完成迹象、风险迹象、正反证据冲突和临界状态都交给 LLM；常规继续状态跳过。慢验证器输出 `continue/advance/repair`。`advance` 后压缩上一阶段轨迹；`repair` 保留已完成前缀，只改被否定的最小范围。修改范围与回退深度分开决定。

**接入。** 规划阶段要求 Qwen 对每个子目标给出可观察的 `preconditions、progress_signals、done_signals、falsifiers`。程序快检动作解析、当前编号有效性、执行异常、错误页和预期变化缺失；在疑似完成、异常、证据矛盾、连续无进展时，向同一 Qwen 提供当前 FCU、最近动作与页面证据，请它输出三分决策和诊断。局部动作错误就重新定位；目标仍对但路径失效就换路径；子目标本身不成立才重写受影响后缀。只有核实前缀的结果仍成立才保留其完成状态。

原文快检还使用 DeBERTa NLI 与 SigLIP2 匹配正反证据；本项目首版采用程序规则和统一 Qwen 路由，不引入未报备辅助模型，也不照抄这些模型的分数阈值。

**代码。** 未定位到公开实现。实现依据是论文 §4、§5、附录 B.1/B.5；其中 FCU 数据结构、三分决策、分层修复最适合独立加入基础 Agent。

## 04 ContractSkill：取步骤契约、结构化错误与最小修补

**问题。** 元素失效、前置页面不对、参数错误、缺少最后一步属于不同错误，全量重写会损坏正确部分。

**论文方法。** 流程显式保存前置条件、步骤、步骤后断言、总后置条件、恢复和终止条件。步骤验证器返回 `(失败步骤、错误码、局部轨迹)`，总验证器判断整体完成。契约可检查 URL、页面文本、表单值及状态变化；目标用当前快照中的角色、文本和稳定属性重新解析。修补只允许替换定位、修正参数、插入前置条件、后置条件或恢复步骤，随后重新验证。

**接入。** 先给基础 Agent 的每个待执行动作加 `expected_pre/expected_post`，下一次观察验证其真实效果。错误码分别进入重新定位、改参数、补中间步骤或恢复分支。平台元素编号每次从当前观察重绑定；保存的是语义目标，不能把旧编号当可复用定位。在线修复保留已核实效果，离线修订执行逻辑时保留必要导航前缀，这两种“保留前缀”分别处理。

**代码。** [env/skill_utils.py](https://github.com/underfitting-lu/contractskill/blob/main/env/skill_utils.py)：`observation_contract_status()` 检查 URL/文本/可点击目标/输入项；`localize_failure()` 将错误映射为 schema、基础设施、契约或执行失败；`allowed_patch_types_for_failure()` 约束修补种类；`repair_targets_against_observation()`、`introduced_invalid_repair_targets()` 检查修补后的目标是否合法；`preserve_navigation_prefix_for_repair()` 保留离线修补时必要的首段导航。网页适配参考 [env/vwa_env.py](https://github.com/underfitting-lu/contractskill/blob/main/env/vwa_env.py)，运行入口是 [run_vwa_experiment.py](https://github.com/underfitting-lu/contractskill/blob/main/run_vwa_experiment.py)。

迁入时先检查契约非空且覆盖对应目标；原函数在空契约时直接返回成功，这一返回值不能代替任务完成判定。

## 05 Agent JIT Compilation：在有效计划中优化关键路径

**理论。** 优化目标应是有效计划的总延迟；动作少、模型调用少不必然更快。循环内的模型调用和长尾等待可能主导总耗时。

**论文方法。** 每个工具声明参数与输出类型、前置与后置状态、可选运行期检查。规划器生成候选代码，用控制流图检查类型和状态流，拒绝不可组合的工具序列，再按工具成本及循环嵌套成本排序。调度器用历史元素交互延迟分布，Monte Carlo 比较串行、任务并行、冗余竞速三种策略：并行耗时含串行部分、最慢 worker 和调度开销，竞速取最快副本并计入开销。

**接入。** 先为任务图边记录前后状态与运行耗时，用当前站点实测更新中位数和长尾；计划校验不通过就交回 Qwen 修正。对可拆的只读节点估算 `串行部分 + max(分支耗时) + 管理开销`，只有能覆盖管理成本才启用多 Tab。模型判断尽量移出逐项处理循环，把页面提取的结构化数据交给本地过滤、排序、比较。候选计划生成也消耗时间，不默认每个任务都生成多份。竞速只作为可取消、无重复写入副作用的只读分支选项。

**代码。** [A1 关联框架](https://github.com/stanford-mast/a1)，论文完整实验实现尚未确认。已核实 [src/a1/codecheck.py](https://github.com/stanford-mast/a1/blob/main/src/a1/codecheck.py) 的 `check_code_candidate()`、`check_syntax()`，以及 [src/a1/codecost.py](https://github.com/stanford-mast/a1/blob/main/src/a1/codecost.py) 的 `compute_code_cost()`、`traverse_cfg_for_cost()`；分别提供计划校验和基于 CFG 的成本排序参考。将其作为关联实现，不把 A1 所有能力视为本文实验复现。

## 08 WebFovea：让动作解析、执行、回执形成一致链路

**问题。** 模型目标判断正确，仍可能因输出解析、焦点、坐标或错误回执反复失败。应先确认失败发生在哪一环。

**论文方法。** 只接受首个 Thought/Action，清理会混入输入框的模板结束标记；截图预处理和点击映射使用实际发送尺寸与视口尺寸比例。执行器统一处理动作，输入后回读值、选择失败返回可用选项。动作前后比较 URL、标题、节点数、文本长度、滚动和焦点等指纹，必要时加文本哈希与子框架指纹。无变化反馈配合执行器预算触发处理，而非仅提示模型“不要重复”。

**接入。** 自动化侧重点迁入严格单动作解析、当前元素校验、输入结果检查和前后观察差异；真实网站视觉分支再接尺寸换算、焦点与 iframe 处理。记录 `intended_action、parsed_action、execution_status、observed_effect`，让诊断区分“没执行”“已执行但没达到目标”“结果待确认”。无变化只是检查信号，不能直接判定失败或终止；重复动作达到预算时改为诊断/换路径。

**代码。** [src/agent/agent.py](https://github.com/jianganghan/WebFovea/blob/main/src/agent/agent.py)：`_truncate_to_first_action()`、`parse_action_to_structure_output()`；[src/agent/web_controller.py](https://github.com/jianganghan/WebFovea/blob/main/src/agent/web_controller.py)：`page_fingerprint()`、`frame_fingerprint()`、`_diff_note()`、`fill_at()`、`select_option_at()`，以及执行总入口 `excute_action()`（原代码如此拼写）。

## 13 Skim：只读任务先尝试便宜路径，失败继承有效进展

**问题与方法。** 稳定网站的搜索、筛选和分页往往有共享导航结构，不必每次完整 ReAct。原文离线建立带参数类型的 URL 模板、搜索语义、答案 schema 与站点能力信息；在线选择模板、绑定参数、取页提取。先做非空/类型/范围检查，再以任务、URL、页面摘要和候选答案做语义验证。失败按原因升级，并从已到达 URL 启动通用 Agent；不传递被拒绝的答案或推理。

**接入。** 只读搜索/信息提取任务匹配经过验证的页面导航方式；利用平台合法 `goto` 到页面，仍从实际观察读取数据。找不到模板或验证失败就把当前 URL 和已确认状态交回基础 Agent。失败原因决定是重新提取、重新定位还是换导航，避免一律重启。首版保留统一 Qwen 和浏览器观察，不迁入原文 HTTP 抓取、外部模型选择；写操作继续正常逐步执行。它最值得迁入的是“验证后接受＋失败只继承可信进展”，不是直接绕过网页。

**代码。** 未定位到公开实现。可依据 §3.3 单独实现 `schema_check → semantic_check → accept/fallback`，fallback 上下文仅加入当前页和确认事实。

## 17 CUADebug：诊断最早因果错误，而不是最后报错

**方法。** 从失败终点向前检查动作前后观察，区分本步独立引入的错误与继承前一步的后果，输出 `root_error_step、taxonomy_tag、evidence、correction、confidence`。每个检查步骤保留意图与真实结果摘要；继续执行时同时提供失败模式、纠正方式和当前需要修复的副作用，而非让 Agent 再看一遍全部历史。

**接入。** 在连续失败、无进展循环或关键契约失败后按需调用诊断，而不是每一步调用。日志将动作前后可访问性树/URL/执行状态对齐，先检查最近异常区间，不够再向前展开。修复提示明确“历史根因”“当前状态”“最小恢复步骤”“接着采用的不同动作”。在线浏览器没有可用快照时，从现状恢复；论文的环境重放/回到根因前一步属于受控实验能力，不当作线上必备接口。

**代码。** [AgentDebugX GUI 模块](https://github.com/AgentDebugX/AgentDebugX/tree/main/src/agentdebug/gui)；[rca.py](https://github.com/AgentDebugX/AgentDebugX/blob/main/src/agentdebug/gui/rca.py) 提供 `RCAResult`、`StepSummary`、`run_rca()`；[tools/__init__.py](https://github.com/AgentDebugX/AgentDebugX/blob/main/src/agentdebug/gui/tools/__init__.py) 的 `get_tools()` 提供诊断工具集合。迁入诊断 schema 和轨迹检查方法，模型客户端换成统一 Qwen。

## 18 ActionEngine：用页面状态图减少逐步规划

**理论与方法。** 页面状态由稳定的功能元素组确定，动态帖子、商品和输入值在执行时绑定；图的边代表实际 UI 可用操作，包括页面跳转和不跳转的数据读取。任务先生成带循环、分支和变量依赖的草图程序，再用 BFS 将抽象 UI 调用链接到图上路径，并检查循环回到下一轮所需状态；执行时按 UI、计算、控制流节点分别处理。异常只修补当前节点或图中的定位信息。

**接入。** 首版按已观察页面积累小型状态图：保存页面类型、当前可用语义操作、观察到的转移，动态数据从最新树提取。让 Qwen 决定高层子目标和分支，本地程序负责图搜索、变量绑定、数量/价格/文本等确定性运算。在单动作协议中把编译计划保存在任务内状态，每次只解析当前目标并返回一步；页面未满足预期时暂停剩余队列，交回基础 Agent 重定位。完整离线爬站与一口气执行程序不是首版前提。

**代码。** 未定位到公开实现。§3 的 `State/Atom/Operation` 和 §4 的三类执行节点适合作为设计依据；论文中的 `MixedActionPlan`、`WebUIWorker` 是原文对象名，未核实为可下载代码符号。

## 28 ReTRACE：恢复完成要能继续执行

**理论。** 页面外观相同不等于状态相同：隐藏选项、未提交输入、会话或数据可能已变化。论文以“恢复后执行原后续动作能否得到正确任务结果”定义转移一致性，再结合可见观察匹配判断恢复。

**方法与接入。** 给恢复分支明确目标检查点：URL/页面类型、必要输入值、已确认业务结果、未完成动作。恢复后核对这些条件，再执行一个合法、低风险的后续步骤并验证其预期结果；只有通过才能将节点从 recovering 改回 running。不能用“回到首页”或模型自称恢复作为完成证据。恢复成功后将上下文截回确认边界，附当前有效状态和短恢复说明，避免继续沿错误历史行动。受控测试中用剩余成功轨迹和最终 oracle 检验恢复；真实网站侧使用页面可观察条件与正常后续步骤，不盲目重放可能重复提交的写操作。

**代码。** [作者仓库](https://github.com/BangProx/ReTRACE) 当前核查材料标注待发布，未提供可移植的执行代码。优先迁入恢复验收标准、显式恢复提示与恢复后上下文重置。
