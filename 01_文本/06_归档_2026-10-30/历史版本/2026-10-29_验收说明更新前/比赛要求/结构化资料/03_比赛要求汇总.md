## 一、赛事与目标

- 赛事：2026年度Hackathon软件难题挑战赛决赛。
- 赛题编号：30。
- 赛题名称：Web Agent 的并行执行与容错调度。
- 出题组织：华为。
- 原题技术领域：鸿蒙应用开发／智能体系统；后续微信群已暂时取消鸿蒙限制。
- 接口专家：沈慧海，shenhuihai@huawei.com。

开发接收自然语言任务指令、自动操作网页完成业务任务的 Web Agent，重点解决批量、跨站任务中的并行执行、结果确认、容错调度和频率控制。

原题背景指出，现有方案存在页面等待耗时大、操作成败反馈不足、异常导致任务链中断、并行与恢复能力不足，以及网站限流等问题。

## 二、任务形态与能力要求

任务以批量信息核对、跨系统数据搬运、多渠道内容分发等业务为主；单次登录后需连续完成大量页面操作。任务拆解、页面理解、操作执行和容错恢复由参赛者自行实现。

原题任务示例：在代码托管网站筛选过去 7 天创建、标签为 bug 且未处理的条目；在内容网站新建周报，标题为“YYYY-WW 周 bug 汇总”，正文列出各条目的编号和标题，并将状态设置为“待审批”。

| 能力 | 要求 |
| --- | --- |
| 并行执行 | 判断依赖关系、执行顺序和并行空间，可同时打开多个页面分别处理。 |
| 结果确认 | 自行决定提交后何时重读页面验证成功、何时继续，权衡确认成本与错误传播。 |
| 容错调度 | 发现页面超时、元素缺失、登录态失效等异常，决定回退点并重调度后续步骤。 |
| 频率控制 | 在目标网站限流约束内提高执行速度。 |
| 人工环节衔接 | 识别登录、二次验证等环节，主动暂停并提示用户，完成后自动恢复。 |

网页操控手段不限，可执行页面脚本、模拟用户输入或使用其他可行方式。该自由度不取消原题对绕过网页直接篡改数据的禁止。

## 四、执行约束与优化目标

原题把以下列为执行约束，违反则该任务记 0 分：任务结果通过验收检查；模型符合端侧可部署或同等算力及参数要求。外部 API 与平台的调整见上一节。

在保证任务成功率的前提下，缩短总耗时，减少冗余页面访问与模型调用消耗，保证操控流畅及资源占用合理。人工干预时间不计入任务时长；能主动识别人工环节并顺畅恢复的方案在评分中从优。

## 五、评测、验收与计时

| 事项 | 要求 |
| --- | --- |
| 评测环境 | 竞赛方部署的模拟环境，包括电商、论坛、代码托管、内容管理等多个网站，站点数据具备真实规模。 |
| 任务下发 | 自然语言指令；用例基于模拟环境设计，于决赛现场公布。 |
| 结果校验 | 每个任务配程序化校验器，按类型检查最终页面内容、目标地址或网站后台数据。 |
| 校验触发 | 任务声明完成后执行验收检查。 |
| 单任务判定 | 通过或不通过，不设部分分。 |
| 失败与超时 | 仅记该任务未完成，不影响其他任务执行与成绩；全部任务完成情况计入成功率，允许一定失败率。 |
| 计时 | 自任务指令下发起，至验收检查执行时止；扣除人工干预时段。 |

## 六、运行日志与审计

应用须输出完整运行日志，至少包含：操作时间、目标页面、动作类型、结果、模型调用量。

原题规定，日志与实际页面操作不符、绕过网页直接篡改数据、预写死任务答案等行为，一经发现取消成绩。原题同时禁止“调用外部模型”，但该项已由微信群“允许外部 API、不得超标”的答复调整；两处原文均保留。

## 八、评分标准

进入排名的门槛：验收通过率不低于 **60%**。

| 维度 | 权重 | 评价内容 |
| --- | --- | --- |
| 成功率与鲁棒性 | 45% | 随机抽取用例的整体验收通过率、失败任务的恢复表现。 |
| 完成时间 | 20% | 已通过任务的总耗时，扣除人工干预时间，按排名分档。 |
| 操控质量 | 15% | 无冗余操作、等待策略合理、性能体验及资源占用；登录等人工环节识别与衔接从优。 |
| 成本控制 | 10% | 页面访问次数与端侧模型调用消耗；成功率达标时，显著小于参数上限的模型酌情加分。 |
| 方案报告 | 10% | 各考察点的设计分析质量。 |
