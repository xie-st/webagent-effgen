# WebAgent 比赛要求

赛题：华为 2026 年度 Hackathon 软件难题挑战赛决赛第 30 题——Web Agent 的并行执行与容错调度。

整理日期：2026-10-30。本文合并现有赛题、群内补充、平台接入指南和验收说明，作为比赛要求的统一查阅文档。验收安排按验收说明，平台操作按接入指南及最新群内能力答复；评分权重与报告要求沿用原题。

## 一、要完成什么

开发一个接收自然语言任务指令、自动操作网页完成业务任务的 Web Agent。自行实现任务拆解、页面理解、行动决策、结果确认和容错恢复，在保证成功率的基础上缩短耗时、减少冗余操作与模型调用。

| 能力 | 要求 |
| --- | --- |
| 并行执行 | 识别依赖与并行空间，协调多个页面、子任务和共享状态。 |
| 结果确认 | 根据实际网页状态判断动作是否成功，合理决定何时检查，避免错误传播。 |
| 容错调度 | 发现超时、元素缺失、登录态失效等异常，回退、恢复并重新调度。 |
| 频率控制 | 在网站限流规则内控制节奏，避免触发冷却或封禁。 |
| 人工衔接 | 识别登录、二次验证等环节，主动暂停并提示用户，完成后自动恢复。 |

## 二、验收内容与安排

验收由 **10 个自动化用例＋1 个真实网站用例**组成。

| 项目 | 自动化用例 | 真实网站用例 |
| --- | --- | --- |
| 环境 | 赛方部署的论坛、电商模拟网站 | 公开真实网站 |
| 用例公布 | 最终用例于验收阶段公布 | 目标网站与任务于验收阶段公布 |
| 完成判定 | 程序化校验器检查最终页面内容、目标地址或后台数据 | 视频连线现场查验 |
| 重点 | 完整完成任务、结果正确、稳定执行 | 真实交互、多 Tab／多子任务并行、限流合规、用户接管与恢复 |

真实网站演示须展示真实页面操作及相对串行执行的耗时收益，浏览器支持用户接管。比赛阶段自行在公开站点验证这些能力。

**比赛阶段**：各队本地开发 Agent，连接共用调测服务器联调，查看结果与回放。调测入口：[WebArena 评测台](https://webarena.94-74-111-115.sslip.io/)。

**验收阶段**：比赛结束后，赛方公布最终验收服务器地址；各队登录并连接 Agent，逐队视频连线，按评委指令执行用例，共享操作过程与日志，当场核对成绩。

**调测成绩不作为最终成绩。最终以验收服务器上的结果和现场查验为准。**

## 三、模型与运行环境

| 事项 | 要求 |
| --- | --- |
| 主模型 | 统一使用 **Qwen3.6-35B-A3B（35B MoE，激活 3B）**。 |
| 辅助模型 | 如使用更轻量的模型辅助，须报备。 |
| 平台调用 | 自动化评测通过 `third_party_agent.model.generate(messages)` 调用统一模型，选手不指定模型、密钥或推理参数。 |
| 开发环境 | Agent 在各队本机运行，开发语言与框架不限，暂不限制鸿蒙；官方连接程序要求 Python 3.10+。 |
| 服务器职责 | 提供模拟网站、浏览器、统一模型调用和判分。各队无需部署模拟环境或另备服务器。 |
| 网络连接 | 本地客户端主动连接评测台，无需开放入站端口。 |

验收说明规定届时提供 API Key；自动化接入指南规定无需自行配置密钥。真实网站演示的具体模型接入与密钥使用方式列于第九节。

## 四、平台接入与调测

### 1. 注册与连接

1. 每队自行注册一个评测台账号并保管。账号不具备找回功能。
2. 下载 `webarena-outbound-client.zip` 并解压。
3. 在「Agent 连接」中新建连接，下载 `agent-connection.json`。连接令牌只在创建时下载一次，不是模型 API 密钥。
4. 将连接文件与 `third_party_agent/`、`my_agent.py`、`agent_logic.py` 放在同一层目录。
5. 在 `agent_logic.py` 的 `decide()` 接入自己的策略，通过 `my_agent.py` 适配平台输入输出。
6. 在客户端根目录启动连接：

```bash
python -m third_party_agent connect --connection-file agent-connection.json --agent my_agent:MyAgent
```

保持客户端与电脑运行，在网页确认「已连接」。连接成功只代表通信正常；默认 `ExampleAgent` 仅返回 `stop`，不能用于评价真实任务能力。

### 2. 输入与动作协议

- 输入包括任务、当前页面观察（类型、URL、可访问性树文本）、历史、动作历史和任务内状态。
- 一个请求只返回一个动作，可返回动作字符串或 `{"action": "click [当前元素编号]"}` 形式的字典。
- 指南列出的常用动作包括 `click`、`type`、`press`、`scroll`、`goto`、`stop`；元素编号必须来自当前观察。完整动作格式以连接包协议为准；最新群内答复已确认自动化评测网站不支持多 Tab，不提供新建／切换 Tab 的执行路径。
- 可替换提示词与决策逻辑，在本机安装算法依赖；自带浏览器框架须适配平台观察与单动作协议。
- 自动化评测网站不开放 curl、JS 注入，不能依赖 evaluate_script；原题允许页面脚本不代表平台开放该接口。截图后续可以提供，开放时间与接口尚未公布，当前 snapshot 不等于 take_screenshot 已可用。Tab 切换、并行操控及进阶方案可在最后一道真实网站题实现与展示。详见[群内能力答复](../比赛要求/结构化资料/02_微信群补充说明.md#6-自动化评测网站能力与真实网站展示)。

### 3. 批次执行与结果

在「评测总览」选择在线 Agent，点击「开始整批评测」。当前接入指南规定固定顺序执行任务，不再自选；浏览器就绪后每项限时 **300 秒**、不限步数，截止后检查最终状态。该时限属于当前平台指南，最终验收时限尚未明确。

每项准备环境时创建新的论坛副本，执行时启动独立浏览器，结束后回收；无需手工恢复网站数据。可关闭或刷新评测网页，但须保持本地连接程序运行。停止整批执行会停止当前与后续任务，已完成结果保留；某项持续无响应时停止该项并继续后续项。

在「运行记录」查看详情和 HTML 操作回放，下载评分 JSON、浏览器 trace、日志及批次报告。模型 token 用量与费用由平台记录、统一结算。

| 平台结果 | 含义 |
| --- | --- |
| 已完成，1 / 1 | 校验通过。 |
| 已完成，0 / 1 | 已判分，任务目标未满足。 |
| 运行失败／已中断，未评分 | 程序、连接或环境中断，需查日志；null 不等于零分。 |
| 已取消 | 没有有效评分。 |

当前论坛平台不提供实时可操作的远程窗口；真实网站演示须另外具备用户接管能力。

## 五、执行、日志与账号规则

**每队同一时间只能运行一个评测任务，按顺序执行，不得并发提交多个任务抢占服务器资源。** 自动化评测网站不支持多 Tab；多 Tab 切换与并行操控在真实网站用例中实现和展示。

每次任务恢复初始数据，结果按账号隔离。验收全程使用本队账号，提供账号供赛方查验，Agent 操作、日志和评测记录须一一对应。账号遗失或无法提供的记录不予认定；不得与其他队伍共用账号、借用或冒用他人记录。

运行日志须完整，至少包含：**操作时间、目标页面、动作类型、结果、模型调用量**。

验收红线：

- 禁止调用其它高规格云端模型、外部 API 或外部算力；统一模型与辅助模型按第三节执行。
- 禁止绕过网页直接篡改数据、预写死任务答案、伪造日志或使日志与实际操作不符。
- 禁止账号混用、借用或冒用他人评测记录。

违反验收纪律可能导致任务记 0 分或取消成绩。

## 六、判定、计时与评分

自动化用例在任务声明完成后执行程序检查。单用例结果为**通过／不通过，无部分分**；失败或超时仅影响该任务，不影响其它任务的执行与成绩。

**验收通过率不低于 60% 才能进入排名。** 真实网站用例计入通过率与分数的方式尚未明确。

计时从任务指令下发起，到验收检查执行时止；登录、二次验证等人工干预时段扣除。

| 维度 | 权重 | 评价内容 |
| --- | --- | --- |
| 成功率与鲁棒性 | 45% | 整体验收通过率、失败后的恢复表现。 |
| 完成时间 | 20% | 已通过任务的总耗时，扣除人工干预，按排名分档。 |
| 操控质量 | 15% | 操控流畅、无冗余操作、等待合理、性能与资源占用；人工环节识别和衔接从优。 |
| 成本控制 | 10% | 页面访问次数与模型调用消耗。 |
| 方案报告 | 10% | 各考察点的设计分析质量。 |

权重来自原题，验收说明未重新调整。原题还规定成功率达标时小模型可酌情加分；当前须结合统一主模型与辅助模型报备要求执行。
