# 比赛要求汇总

依据：[原题](01_赛题网页正文转录.md)、[微信群补充](02_微信群补充说明.md)、[接入指南](04_WebAgent评测平台接入指南.md)、[验收说明](05_WebAgent赛题验收说明.md)。更新：2026-10-29。

当前验收构成、统一模型、环境和账号纪律按验收说明整理；自动化平台接口按接入指南整理。原题中未被后续材料调整的评分与交付要求继续保留。四份来源各自保留原文。

## 一、赛事与目标

- 赛事：2026年度Hackathon软件难题挑战赛决赛，第 30 题。
- 赛题：Web Agent 的并行执行与容错调度，出题组织为华为。
- 接口专家：沈慧海，shenhuihai@huawei.com。

开发接收自然语言任务、操作网页完成业务任务的 Web Agent，重点在并行执行、结果确认、容错调度和频率控制。原题以鸿蒙应用为场景，微信群已暂时取消鸿蒙限制；验收说明明确开发语言与框架不限。

## 二、验收构成与阶段

**10 个自动化用例＋1 个真实网站用例。**

| 项目 | 当前要求 |
| --- | --- |
| 自动化用例 | 在赛方部署的论坛、电商模拟环境执行，任务声明完成后由程序化校验器核对结果。 |
| 真实网站用例 | 目标网站与任务在验收阶段公布，通过视频连线现场演示，查验真实交互、并行化、限流合规和人工介入衔接。浏览器需支持用户接管与多 Tab 并行处理。 |
| 比赛阶段 | 各队共用调测服务器，内置少量调测用例；本地开发 Agent，连接评测台联调，并自行在公开真实网站自测。 |
| 验收阶段 | 比赛结束后公布最终验收服务器地址，逐队视频连线，按评委指令执行 10＋1 用例，现场核对结果与账号记录。 |
| 成绩依据 | 调测成绩不作为最终成绩；以最终验收服务器上的评测结果和现场查验为准。 |

原题列举过代码托管、内容管理等网站和跨站业务示例；最终环境范围按上述验收说明准备。

## 三、模型、部署与平台接口

| 事项 | 当前要求 |
| --- | --- |
| 验收模型 | 统一使用 **Qwen3.6-35B-A3B（35B MoE、激活 3B）**。更轻量的辅助模型须报备。 |
| 模型调用 | 自动化接入指南要求通过 `third_party_agent.model.generate(messages)` 调用平台统一模型；选手不配置模型、密钥或推理参数。 |
| API 与算力 | 早期群答复允许不超标的外部 API；当前验收说明统一指定模型，并禁止其它高规格云端模型、外部 API 或外部算力。不能沿用“符合参数即可任意选外部 API”的旧选型口径。 |
| 本地开发 | Agent 与运行日志在各队本机；无需本地部署模拟站点或另备服务器。客户端主动向平台连接，无需开放入站端口。 |
| 调测地址 | https://webarena.94-74-111-115.sslip.io/ 。最终验收地址于比赛结束后另行公布。 |
| 平台职责 | 按接入指南，服务器负责模拟网站、浏览器、模型调用和判分；本地 Agent 接收任务与页面观察，返回动作。 |
| 输入输出 | 当前接入指南支持可访问性树文本和当前元素编号；一个请求返回一个动作，常用 `click`、`type`、`press`、`scroll`、`goto`、`stop`。 |
| 接入方式 | Python 3.10+；在 `agent_logic.py` 的 `decide()` 接入逻辑，经 `my_agent.py` 转换成平台动作。截图坐标或自带浏览器的 Agent 需做接口适配。 |

验收说明称届时提供 API Key，接入指南称自动化平台统一调用、无需选手配置密钥；两者分别保留。真实网站演示如何使用统一模型、密钥如何发放，仍待赛方明确，不能据此自行启用其它服务。

## 四、能力与执行约束

| 能力 | 要求 |
| --- | --- |
| 并行执行 | 判断依赖与共享状态，多页面、多子任务并行推进，展示相对串行的耗时收益。 |
| 结果确认 | 根据实际网页状态确认动作结果，决定何时重读页面、何时继续。 |
| 容错调度 | 处理页面超时、元素缺失、登录态失效等异常，保留进度并恢复。 |
| 频率控制 | 在目标网站频率限制内运行，控制节奏，避免冷却或封禁。 |
| 人工衔接 | 识别登录、二次验证等环节，暂停并提示用户，完成后自动恢复。 |

**评测任务之间按队串行，任务内部研究并行。** 每队同一时间只能运行一个评测任务，不能并发提交多个任务抢占服务器资源。真实网站多 Tab 并行属于用例内部能力；自动化平台是否提供相应动作，需按下载包实际协议确认。

原题允许页面脚本、模拟输入等网页操控手段；自动化接入实际受平台动作协议约束。不得绕过网页直接改后台数据、预写死任务答案或伪造日志。

## 五、判定、计时与调测细则

| 事项 | 要求 |
| --- | --- |
| 结果校验 | 程序化校验器按任务类型检查最终页面内容、目标地址或后台数据，任务声明完成后执行验收检查。 |
| 判定 | 单个用例只有通过／不通过，无部分分；通过率不低于 **60%** 才能进入排名。 |
| 计时 | 从任务指令下发至验收检查执行，登录、二次验证等人工干预时段扣除。 |
| 数据与隔离 | 每次任务恢复初始数据，评测结果按账号隔离，可回放真实操作与结果。 |
| 失败处理 | 原题规定单任务失败或超时不影响其它任务成绩；接入指南中的批次按顺序推进，持续无响应的项目停止后继续后续项。 |

接入指南描述的当前整批调测为固定顺序 10 项论坛任务；浏览器就绪后每项限时 **300 秒**，不限步数，截止检查最终状态。该平台细则不等于最终 10 个用例的内容或统一时限；最终验收说明列明论坛、电商两个站点，未公布具体用例与单任务时限。

平台可下载评分 JSON、浏览器 trace 和日志。`1 / 1` 为检查通过，`0 / 1` 为已判分但目标未满足；未评分、中断或取消需分别记录。当前论坛平台没有实时可操作的远程窗口，不能代替真实网站用户接管能力的验证。

## 六、日志与账号纪律

完整日志至少包含：**操作时间、目标页面、动作类型、结果、模型调用量**。Agent 操作、日志输出和平台记录须一一对应；日志与实际操作不符、绕过网页改数据、预写答案或违规调用模型等，按验收纪律处理，可能记 0 分或取消成绩。

每队自行注册并保管一个账号，不与其它队伍共用。接入指南提示账号无找回功能、连接令牌仅在创建时下载一次。验收时提供本队账号查验；账号遗失或无法提供的记录不予认定，混用、借用或冒用记录取消成绩。

## 八、评分标准

以下为原题权重，新验收说明未重新列权重；**60% 门槛与二值判定已再次明确**。

| 维度 | 权重 | 原题评价内容 |
| --- | --- | --- |
| 成功率与鲁棒性 | 45% | 整体验收通过率、失败任务的恢复表现。 |
| 完成时间 | 20% | 已通过任务总耗时，扣除人工干预时间，按排名分档。 |
| 操控质量 | 15% | 冗余操作、等待策略、性能与资源占用，人工衔接从优。 |
| 成本控制 | 10% | 页面访问与模型调用消耗；原题另有小模型酌情加分表述，现应结合统一模型和辅助模型报备要求理解。 |
| 方案报告 | 10% | 各考察点的设计分析质量。 |

真实网站用例如何计入通过率、各项分数如何汇总，新材料没有进一步说明，不据“10＋1”自行推算最低通过个数。
