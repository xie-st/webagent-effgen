# 智能体改动起点选型

日期：2026-10-30。任务归属：华为 WebAgent 比赛的本地测试与基线选型。记忆范围仅当前对话、协作规则、指定比赛材料及本项目论文；公开检索仅用于查证一手论文、官方代码与文档。本文记录研究判断，不声称已经完成五个智能体的比赛接入或端到端模型评测；安装与测试结果以“本地测试环境”中的实际记录为准。

## 核心判断

推荐五个具体实现：**AgentLab GenericAgent、AgentOccam、browser-use Agent、smolagents ToolCallingAgent、OpenHands SDK Agent**。它们分别覆盖可控的 Web 实验基线、精简观察动作、真实浏览器工程、轻量通用循环和完整通用运行时。

最适合先改的是 **GenericAgent**：单步决策、AXTree、可替换模型层和可配置提示词都贴近比赛接口。**AgentOccam** 适合做精简对照，**browser-use** 适合真实网站演示。通用方案先试 **smolagents**；只有确实需要完整事件恢复、复杂工具组织时，再承担 **OpenHands** 的适配成本。

这里选择的是“可改的决策循环与运行时”，不是各项目自带的模型、云服务或历史榜单分数。

## 判断依据与评估方式

官方自动化接口当前只提供可访问性树、URL、历史与任务内状态；每次返回一个动作。模型调用固定为 `third_party_agent.model.generate(messages)`。因此，现成框架“支持 Qwen/OpenAI compatible”并不代表能直接接赛方模型：必须换成消息回调适配，并将输出限制为官方动作白名单。自动化禁止多 Tab、JS 注入和 curl；真实网站单独实现并行、限流与接管。

优先级为：成功率与恢复能力 → 当前接口改造成本 → 单步时间及调用量 → 真实网站工程能力 → 方便比较和定位失败。论文作者的任务成功率、步数、token、软件工程分数是其评价方式；本文的起点排序是依据比赛约束作出的工程判断，两者不混为一个榜单。

事实核查 **9/10，达标**：关键接口判断来自指定比赛材料；候选结构、许可证与维护日期核对官方仓库。没有用别的模型的论文成绩估算 Qwen3.6-35B-A3B 成绩。

## 五个候选

### 1. AgentLab 的 GenericAgent：自动化主线首选

作者面对的是 Web Agent 基准、环境与评测方式彼此割裂的问题，因此把 BrowserGym 的浏览器接口、AgentLab 的实验工具和可配置 GenericAgent 分开。其研究目标是统一可复现比较，而非设计一个依赖特定模型的复杂策略。

论文以多模型、多基准成功率为主，同时记录步数、token 与成本。已读正文、相关工作、动作集附录 A、基准说明 B、提示词示例 C、设置 E、成本 F；实验对其“统一生态可完成大规模比较”的核心故事支撑 **8.5/10，达标**。[论文](https://arxiv.org/html/2412.05467)

源码 `GenericAgent.get_action(obs)` 拼装当前观察、行动历史、记忆、计划与提示词，调用可替换聊天模型，解析单步动作并返回 `AgentInfo`。它已有解析重试和状态 reset；“解析重试”与网页业务失败恢复须分别处理。[决策循环](https://github.com/ServiceNow/AgentLab/blob/8488c564eea0525aaff5dea189bb03a9b529546e/src/agentlab/agents/generic_agent/generic_agent.py)

改造入口：新建赛方聊天回调；输入映射到 GenericAgent 需要的字段；仅启用当前允许的观察和动作。把网页变化、执行错误、完成证据和重复行动检测放入状态。先保留结构，按调用预算裁剪历史和提示词。

Python `>=3.11,<3.13`；Apache-2.0，已核对 LICENSE 与包元数据。AgentLab 是框架，本文推荐其中的 **GenericAgent**，没有把框架名冒充算法。[仓库与安装](https://github.com/ServiceNow/AgentLab)

### 2. AgentOccam：低复杂度的专用 Web 对照

作者认为问题首先在观察、动作表示与语言模型已有能力不匹配，所以优先减少干扰动作、压缩页面结构、选择性保留历史，并让模型用 `branch/prune` 维护计划树。这条研究判断适合用来检验“我们是否先把输入输出做对了”。

已读正文与相关工作，以及动作集 A、关键节点及计划树 B、真实网站 C、跨模型 D。实验对“观察与动作对齐本身有效”的核心故事支撑 **8.5/10，达标**。原研究主实验模型不是比赛 Qwen。[论文](https://arxiv.org/html/2410.13825)

上游提供明确的 actor 配置、纯文本观察和行动输出；原生 `act(objective, env)` 自己驱动环境循环。比赛适配应拆出一轮决策，将 `note/branch/prune` 变成本地状态操作，最终仅返回一个官方动作。[源码](https://github.com/amazon-science/AgentOccam/blob/c078ba629212ea7cee35b2718dc8df72c05e57c7/AgentOccam/AgentOccam.py)

**不照搬“去掉滚动”**：原论文同时使用全页内容。赛方观察若只暴露部分内容，保留 `scroll` 才完整。原观察优化还利用结构化树；官方若只给展平文本，不能假设拿到了相同结构。

改造入口：先迁移提示词、动作精简、摘要和计划状态；保留当前元素编号；把停止条件改成有页面证据的完成判断。Apache-2.0；上游研究代码最近推送时间为 2025-01-28，适合固定版本抽取逻辑。[仓库](https://github.com/amazon-science/AgentOccam)

### 3. browser-use Agent：真实网站演示首选

项目要解决真实浏览器自动化的工程接入，因此把 Agent、浏览器会话、页面表示、工具及模型适配组织成现成库。推荐它主要依据工程接口与源码；本次未找到并完整阅读一篇足以独立验证当前库全部能力的同名研究论文，不给“论文实验分”冒充核验。

已核对本地浏览器与自选模型用法；当前模型协议是 `BaseChatModel.ainvoke(messages, output_format, ...)`，官方代码提供暂停/恢复和并行示例。[模型接口](https://github.com/browser-use/browser-use/blob/2cc71890e65056b67fdb29d98bb407749c15bb08/browser_use/llm/base.py)、[Agent](https://github.com/browser-use/browser-use/blob/2cc71890e65056b67fdb29d98bb407749c15bb08/browser_use/agent/service.py)

改造入口：真实站点保留本地浏览器；按任务分配独立页面／会话，加入站点级并发上限、限流退避、登录暂停与恢复。上游共享会话并行示例明确属于实验性用法，不能将一次 `asyncio.gather` 当成共享焦点、登录态和写操作的冲突处理。[并行示例](https://github.com/browser-use/browser-use/blob/2cc71890e65056b67fdb29d98bb407749c15bb08/examples/features/parallel_agents.py)

迁移自动化平台时需要替换浏览器观察和执行层，改造比 GenericAgent 大。`use_vision=False` 与 `max_actions_per_step=1` 有助对齐，但仍须替换动作和模型层；禁用额外模型调用路径。MIT；当前主分支版本声明 0.13.14，Python `>=3.11,<4.0`。[仓库](https://github.com/browser-use/browser-use)

### 4. smolagents 的 ToolCallingAgent：轻量通用对照

项目希望用少量抽象支持工具推理，提供 CodeAgent 与 ToolCallingAgent。前者把代码作为行动，后者使用结构化工具调用。比赛当前要求单步浏览器动作，因此选 **ToolCallingAgent**；CodeAgent 保留作真实网站或离线受控实验的替代分支。

已核对官方导览、模型基类 `Model.generate()`、工具代理和单步循环。其模型输出需要形成 `ChatMessage` 和结构化 `tool_calls`，不能只把赛方返回字符串塞入现成客户端。可在自定义模型中把工具 schema 写入 messages，解析模型文本，再构建统一输出。[导览](https://huggingface.co/docs/smolagents/en/guided_tour)、[模型源码](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/models.py)、[Agent 源码](https://github.com/huggingface/smolagents/blob/96f33faaf028479119ec8d34507b47694cf14e34/src/smolagents/agents.py)

CodeAct 的连续研究解释了为何代码行动可以组合控制流和数据流；已读其正文、方法和工具评测，但本次未逐读全部数据构造附录。该结果不能当成 ToolCallingAgent 在本比赛上的验证；不给它同一个实验分。[CodeAct 论文](https://arxiv.org/html/2402.01030)

改造入口：只注册官方网页动作；限制一次只允许一项执行，逐步接收赛方新观察；复用回调、记忆和预算控制，再补完成检验。不能让内部 `run()` 在缺少新观察时连续操作。Apache-2.0；Python `>=3.10`。[仓库](https://github.com/huggingface/smolagents)

### 5. OpenHands SDK Agent：完整通用运行时对照

作者的连续路线是 CodeAct → OpenHands 软件智能体 → 模块化 SDK。SDK 论文针对早期单体系统中状态分散、执行环境耦合与恢复困难，采用事件日志、单一会话状态、类型化工具及可选隔离。对比赛最有价值的是可审计恢复和运行控制。

已读 SDK 正文、相关工作、架构与可靠性评价。实验对“架构重构减少运行时故障并保留软件智能体能力”的故事支撑 **8/10，达标**；它的证据不是本比赛网页操作成功率。[论文](https://arxiv.org/html/2511.03690)

当前推荐 `software-agent-sdk`，不把老版 CodeActAgent、旧 BrowsingAgent 与最新 SDK 视作同一个安装入口。模型层 `LLM.completion()` 返回结构化 `LLMResponse`，通常走 LiteLLM；赛方接入仍需要自定义消息回调与结构化结果包装。[模型源码](https://github.com/OpenHands/software-agent-sdk/blob/641e161178cb934f38afcbe603125950611d1668/openhands-sdk/openhands/sdk/llm/llm.py)

改造入口：只给浏览器协议工具，复用会话状态、事件、暂停恢复、卡住检测与上下文压缩。恢复时重新读页面确认动作是否已生效，不能因为日志回放而重复提交表单。默认终端、文件、外部 API 工具不进入官方动作集合。MIT；当前包版本声明 1.59.0，Python `>=3.12`。[SDK 仓库](https://github.com/OpenHands/software-agent-sdk)

## 扩展方案的比较结论

| 方案 | 本次定位 | 决定依据 |
|---|---|---|
| Agent-S S3/S4 | 视觉和桌面路线储备 | 当前官方仓库已包含 S4；核心是屏幕、grounding 与桌面执行，当前自动化只给 AXTree，迁移会替换其关键接口。不是因“不通用”排除。[官方仓库](https://github.com/simular-ai/Agent-S) |
| LangGraph / LangChain ReAct | 可选调度层 | LangGraph 提供状态、检查点、interrupt/resume；它本身不提供网页感知和执行智能体。适合包在选定 Agent 外层；若另造完整 Web Agent，应以新实现身份参加比较。[官方文档](https://langchain-ai.github.io/langgraph/reference/) |
| FCPAgent | 检验恢复的设计来源 | 本地全文含计划—检验—修复及附录；其快检验还使用 NLI／图文模型，原样引入涉及辅助模型和截图。已阅读关键方法与实现细节；本次未核实可复用官方开源工程，不列成现成可安装起点。[原文](https://arxiv.org/html/2607.24167v1) |
| Skim | 效率研究参考 | 已阅读本地方法、实现及评测设置；其直接 HTTP 获取和专用站点配置路径不满足当前官方浏览器动作边界，因此只迁移“快路径必须可验证、失败可回退”的思想。[原文](https://arxiv.org/html/2605.16565v2) |
| Agent Workflow Memory / 工作流技能 | 主基线后的能力模块 | 适合抽取成功轨迹形成经验；先需要稳定决策循环与合规的模板边界，不单独解决浏览器运行、接管、限流。本文没有完整审阅其全部论文与代码，不据此作性能排序。 |
| UI-TARS 等专用模型 | 当前不作为模型替换 | 验收主模型固定；不能把更换为专用视觉策略模型当作当前可直接采用的改动路线。 |

## 实施含义

维护一个统一的 `任务＋观察＋历史＋状态 → 单动作` 接口。五个起点在相同动作白名单和同一模型下比较；真实站点执行器独立于官方执行器。先跑 GenericAgent 与 AgentOccam 的自动化对照，再用 browser-use 搭真实站点执行；smolagents 与 OpenHands 用于判断通用运行时带来的收益是否抵得过改造成本。

论文启发优先迁入三处：显式完成证据、按失败范围恢复、按需要触发模型检查。并行只在真实网站、独立任务和不冲突的页面上开展；AgentLab 的“并行实验”与一个业务任务内部的并行不是一回事。
