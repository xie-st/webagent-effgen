# 验证、模型调用与钩子

对应论文清单 03、06、09、26、27、29、30、31、32。下文分别说明论文方法、项目接入和代码入口。

## 03 The Art of Building Verifiers：把完成判断变成逐项证据核对

**研究思路。** Agent 的“我已完成”会掩盖遗漏条件；只看最后页面又会丢掉提交过程中的关键证据。作者将标准生成、证据选择、评分拆开，避免根据实际表现倒推宽松标准。过程正确和目标达成分开记录；比赛停机必须由目标达成决定。

**方法。** 在第一次行动前，仅根据任务生成互不重复的要求，保留条件分支。执行中按要求保存相关状态证据；结束时分别检索每条要求最相关的页面片段，而非把全部历史重新塞给模型。验证输出应携带逐项状态、证据与未完成原因。

**项目接入。** 增加 `criteria[{id, requirement, condition, status, evidence_refs}]` 与证据索引。URL、AX 树片段、动作回执都带步骤号和时间。`stop` 前先程序检查明确字段，再由同一 Qwen 对未决要求核对；存在 `unknown` 或 `unsatisfied` 就返回缺失项，继续当前任务。过程得分只服务诊断，不据此宣布通过。论文的截图相关性矩阵迁为“要求—AX证据片段”检索属于我们的适配。

**代码。** [Fara 验证命令](https://github.com/microsoft/fara/blob/main/webeval/scripts/verify_trajectories.py)；[MMRubricAgent](https://github.com/microsoft/fara/blob/main/webeval/src/webeval/rubric_agent/mm_rubric_agent.py) 中 `_generate_rubric`、`_score_screenshot_criterion_relevance`。复用标准、证据组织和输出结构；将模型客户端接到官方统一入口。

## 06 Are Online Skill and Memory Modules Always Worth Their Tokens?：先保住行动预算

**问题。** 辅助规划、总结、检索和检查都消耗同一个任务预算；只统计 actor 调用会误判优化收益。论文把所有模块的输入输出 token 合并计费，并将附加模块与可多走几步的基础代理对照。

**方法。** 每次调用记录 `module, input_tokens, output_tokens, duration, task_id`；聚合 actor、planner、verifier、memory 的总成本。其低成本基线用程序去掉 AX 树父子重复文字，将节省预算留给行动；跨多次运行观察稳定完成比例，而非只挑一次最佳成绩。

**项目接入。** 在统一 `generate(messages)` 包装层计数，任务状态保留剩余时间与已用调用。确定格式、元素存在、重复内容去除交给程序；只有程序无法判定的语义问题追加 Qwen。基础代理、加验证、加上下文模块分别记完整成本。不要机械照搬论文的 10/15 步上限，本题按实际时限管理。

**代码。** [AX 去重实现](https://github.com/ServiceNow/budget-constrained-web-agents/blob/main/constbudg/utils/prune_axtree.py)：`parse_axtree`、`should_remove_static_text`、`prune_axtree`；[实验入口](https://github.com/ServiceNow/budget-constrained-web-agents/blob/main/constbudg/run_online.py)；[token 分析](https://github.com/ServiceNow/budget-constrained-web-agents/blob/main/scripts/analyze_log_tokens.py)。技能验证与成本准入另见[技能构建与复用](技能构建与复用.md)。

## 09 ALTK：在动作边界拦截错误，按回执识别静默失败

**方法优势。** 生命周期钩子把三类错误分开：模型输出语法错、工具语义和前提错、工具返回正常但业务未完成。SPARC 先做确定性 schema 检查，再做语义检查；Silent Error Review 将回执区分为完成、部分完成、未完成。

**项目接入。** 在 `decide()` 返回动作前检查动作白名单、参数个数、当前元素编号和字段类型；失败时不发给浏览器，将具体错误反馈同一 Qwen 修正。收到下一次观察后，结合上次预期和新 AX 状态核验结果；“点击无异常”不等于“提交成功”。程序明确识别的错误直接处理，只有不明情况进入语义钩子。钩子输出统一为 `{status, evidence, repair_hint}`，写入任务状态，下一次决策只带相关修复信息。

**代码。** [SPARCReflectionComponent](https://github.com/AgentToolkit/altk-boost/blob/main/altk/pre_tool/sparc/sparc.py)；[Silent Review](https://github.com/AgentToolkit/altk-boost/blob/main/altk/post_tool/silent_review/silent_review.py) 中 `BaseSilentReviewComponent`、`SilentReviewForJSONDataComponent`。比赛 AX 文本需自行适配输入，原组件的 API 语义判断不能直接等同网页判定。

## 26 Beyond Prompts / PRISM：按失败原因修改正确层次

**问题与方法。** 相同失败可能来自指令，也可能来自动作参数、回执和中间件；只加提示词会累积冗余。PRISM 同时搜索 prompt 和工具边界中间件，依据失败集合产生针对性变体，保留成功率与可靠性的 Pareto 候选；修复、门控、最终评价使用不同数据。

**项目接入。** 离线把 trace 归为“目标误解、元素失效、格式错、静默失败、状态遗漏、循环”。目标误解改提示词；格式/元素错改程序校验；静默失败改结果钩子。每个候选只动一个明确机制，记录相对 baseline 的差异；用独立任务确认后再进入现行配置。优化器所用模型同样接统一 Qwen，不照搬仓库中的外部 proposer 配置。

**代码。** [PRISMOptimizer](https://github.com/airbnb/agent-harness-optimizer/blob/main/agent_harness_optimizer/optimizers/prism/loop.py)；[Benchmark 接口](https://github.com/airbnb/agent-harness-optimizer/blob/main/agent_harness_optimizer/framework/benchmark.py)；[中间件编辑面](https://github.com/airbnb/agent-harness-optimizer/blob/main/agent_harness_optimizer/utils/middleware_surface.py)。主要借鉴离线改进流程，不把完整搜索放进单任务执行。

## 27 Monitoring Web Agents Without Internal Signals：用实际轨迹触发检查

**方法。** Macro 特征从现有日志提取重复、循环、动作使用、执行及定位错误，无需追加模型调用；Micro 特征在同一上下文重复查询“意图—动作—预期变化”，观察一致性。论文用正则化逻辑回归预测轨迹前缀风险；失败轨迹的最早未纠正关键错误之前不能全部标为失败。

**项目接入。** 每步维护规范化动作签名、页面签名、近期转移、定位错误计数和已满足要求数量。重复动作且页面不变、页面往返且要求无进展时触发局部核验，将相关窗口交给 Qwen，输出继续、换策略或恢复。阈值规则是我们的低成本起点；收集标注后才能称为论文的学习式风险预测器。Micro 与 CATTS 共用候选采样，避免为监控重复收费。

**代码。** 当前清单和已有核查未定位公开实现。可依据原文 §3.2、附录 D 的特征定义实现，不伪造代码入口。

## 29 CATTS：已有动作分歧时才付仲裁成本

**理论与方法。** 将相同状态下采样的动作按语义等价聚类，得到票数概率 `p(a)`。以熵 `H=-Σp log p` 或 `1-(p1-p2)` 表示分歧；低分歧直接用多数动作，高分歧再让同一模型看观察、候选与票数作仲裁。它门控的是仲裁，候选采样本身仍然付费。

**项目接入。** 插在“模型候选动作→执行前校验”之间。先把无效元素与非法格式剔除，规范化动作后聚类；编号必须属于同一份当前观察。预算充足、关键分支才启用多候选是本项目进一步门控，不是论文原算法。仲裁只产出一个动作，经当前观察再校验后返回平台。固定温度等推理设置不改；重复调用若没有有效分歧则不继续增加候选。

**代码。** 未定位公开实现；原文 §3–4、附录 B 给出候选去重与仲裁结构。可直接实现票数、熵和 margin 运算，无需 logits 或额外模型。

## 30 STITCH：每种任务只启用需要的控制模块

**理论。** 固定全开框架会为不需要的机制付出成本；作者在明确的加性收益和有效实现假设下，比较固定机制与按任务选择机制的期望效用。可用判断是“机制有适用范围”，不是无条件证明动态组合总会更好。

**方法与迁入。** 将本项目已有的重复检测、状态摘要、提交前核验、缺失参数检查注册为控制原语，每项写输入、输出、依赖和启用条件。开始时由 Qwen 输出模块选择配置，程序检查合法性并组装固定钩子顺序；不让模型临时生成执行代码。共享状态保留观察、上次动作、要求和证据；配置无效则使用基础循环。在线只选模块，离线再修模块实现。

**代码。** 未定位公开实现。论文 §4.2–4.3 及附录 B–D 可作原语契约与组合配置依据。本项用于选择运行时控制钩子；技能流程由[技能构建与复用](技能构建与复用.md)中的执行器承载。

## 31 Are We Done Yet?：不通过就带具体理由原地续做

**方法优势。** 独立 judge 接任务与当前截图，返回完成判断和解释；不通过时将解释送回 actor，从当前状态续做。最值得复用的是终止反馈闭环。

**项目接入。** 拦截 actor 的 `stop`，传任务要求、当前 AX 状态和相关证据给同一 Qwen；返回 `{complete, unmet_requirements, evidence}`。未通过只补做缺失项，保留已经确认的工作。与 03 共用一个最终验证器：03 提供标准和证据组织，31 提供续做闭环，避免重复调用两个 judge。AX 替代截图是我们的赛题适配。

**代码。** [评估协议](https://github.com/martasumyk/vision-based-judge/blob/main/evaluators/base.py)：`EvaluationResult`、`VlmEvaluator.evaluate(task_description, screenshot_path)`；[评估器目录](https://github.com/martasumyk/vision-based-judge/tree/main/evaluators)。这里借鉴判定/反馈接口，运行仍使用统一 Qwen。

## 32 SCOPE：把重复失败改写为可执行提示规则

**方法。** 用步骤轨迹和现行提示生成修正规则；候选筛选后将任务内规则与跨任务规则分开。长期规则经过冲突解决、包含关系去重与合并，避免越积越长。规则按 Agent 角色归属，错误发生后即可在后续步骤生效。

**项目接入。** 优先离线从失败 trace 提取“触发条件→具体动作→检查条件”的短规则；在线只注入当前失败相关的临时规则。提示版本与来源 trace 同步记录；任务结束清空临时规则。长期规则经过独立任务确认再纳入项目提示，不把一次失败的对象、网址或答案固化。规则数量上限按输入预算配置，不将论文的阈值直接当本题最优值。

**代码。** [SCOPEOptimizer](https://github.com/JarvisPei/SCOPE/blob/main/scope/optimizer.py)：`on_step_complete`、`get_strategic_rules_for_agent`；[提示模板](https://github.com/JarvisPei/SCOPE/blob/main/scope/prompts.py)；[规则整理](https://github.com/JarvisPei/SCOPE/blob/main/scope/memory_optimizer.py)。不同角色的 synthesizer 仍接同一统一模型。
